# 16 · 上一轮总结卡：定稿方案

本文是 [`15-上一轮总结卡优化建议.md`](./15-上一轮总结卡优化建议.md) 的定稿版：补齐三份外部实现的核对结果，把 P0–P4 重排成可直接施工的顺序，并给出验收标准。

15 记录的是「Qoder 有什么、我们差什么」；本文记录的是「**综合四份实现之后，我们最终该做什么，以及每一项为什么这样做**」。两文并存，15 作论证底稿，本文作施工依据。

---

## 结论摘要

| 维度 | 外部实现怎么做 | 本项目现状 | 定稿决定 |
| --- | --- | --- | --- |
| **生成时机** | 全部在关键路径之外（OpenCode 后台 fiber、Qoder 12s/35s 定时器、Claude Code 阈值触发） | **面板请求里同步 `await`，最长等 20 秒** | **P2 改掉，这是唯一一个「三家都做了、只有我们没做」的点** |
| **输出格式** | 结构化（OpenCode 七段 Markdown、Claude Code 九段、Qoder 强制 JSON） | 纯文本，只 `trim().slice()` | **保持纯文本**。它们的结构是给**机器**续接用的，我们的读者是**人** |
| **失败处理** | 分类错误码 + 稳定对外文案（Qoder 7 个码、OpenCode error type） | 把英文 `reason` 直接当正文渲染 | **P0 中文化，原文进 `title`** |
| **新鲜度** | Qoder 卡片显式显示「更新于 {{time}}」 | 无任何时间信息 | **P1 加更新时间** |
| **输出卫生** | 三道（Qoder 清洗链、OpenCode `NUDGE` 重试、Claude Code 剥 `<analysis>`） | 只有 `trim()` | **P3 补清洗，但不抄它们的粗暴规则**（见 §3.P3） |
| **增量续写** | Qoder 用 `previousRecap` 续写 | 单轮独立摘要 | **不做**。我们的卡叫「上一轮」，语义就是单轮；要改的是命名不是机制 |
| **校验重试** | OpenCode 发 `NUDGE` 再试一次；Claude Code 检查模板标题是否填满 | 无 | **不抄**。自由文本的唯一可校验性质是「非空」，我们已经做了 |

一句话：**三家外部实现的目标是「让下一个 agent 能接手」，我们的目标是「让人扫一眼就知道刚才干了什么」。这个差异决定了输出格式、长度、结构全部不同；但「不要在关键路径上等模型」是所有摘要系统的共性，与读者是谁无关。**

## 一、先把问题定准：我们和三家外部实现解决的不是同一个问题

这一步不澄清，后面的取舍全都会错。

### 1.1 三家外部实现对照

| | OpenCode `compaction.ts` | Claude Code `compact/prompt.ts` | Qoder `recap` |
| --- | --- | --- | --- |
| **触发** | 上下文接近上限（`auto`）、provider 刚拒绝（`overflow`）、手动 `/compact` | 5 层阶梯：microcompact → snip → collapse → auto → reactive(413) | 回合结束后 12s（首次）/ 35s（增量） |
| **输出** | 七段 Markdown：`## Objective` / `## Requirements` / `## Decisions` / `## Work State`(`### Completed` `### Active` `### Blocked`) / `## Next Move` / `## Relevant Files`（≤15 条）/ `## Important Context` | 九段：primary request and intent / key technical concepts / files and code sections / errors and fixes / problem-solving / **all user messages verbatim** / pending tasks / current work / optional next step | 单段散文，150–190 字，最多 220 字，禁标题禁列表禁 Markdown |
| **读者** | 下一个 agent | 下一个 agent | **人**（离开工位的人回来扫一眼） |
| **长度预算** | 由窗口余量决定 | 由窗口余量决定 | 硬上限 240 字（`rQ0`），超了 `slice(0,239)+"…"` |
| **失败** | 一次 `NUDGE` 重试，仍失败报 `compaction.failed` | 检查模板标题是否出现；未填满则报错 | 不写库、不重试，只上报 `{sessionId,model,incremental,durationMs,errorKind}` |
| **持久化** | 写进会话历史，替换被压缩的区间 | 同 | `chat_session_recaps` 表，主键 `session_id` |

### 1.2 根本差异：机器读 vs 人读

三家里有两家（OpenCode、Claude Code）的输出会被**喂回模型上下文**，所以必须结构化——机器要能稳定解析出「哪些做完了、哪些卡住了、下一步是什么」。Qoder 的 recap 只给人看，所以它要求散文、禁列表、限字数。

**本项目属于第三类**：`packages/ui-evolve/lib/summarise.js` 的输出只进侧栏卡片，永不回灌上下文。所以：

- 结构化输出的**收益为零**（没有机器消费者）
- 结构化输出的**成本非零**（多一种失败模式：解析失败；多一段只对机器有意义的模板占位文本）
- **结论：保持纯文本。** 这条决定不受外部实现影响。

### 1.3 交叉验证出的两条硬结论

**结论一：没有任何一家在用户请求里同步等模型。**

- OpenCode：`precompute` 是 `Effect.forkIn(scope)` 的**后台 fiber**，注释写得很直接——「The summary is held, not applied」（摘要只生成不应用），且只在「离上限还有 `PRECOMPUTE_LEAD` 余量」时才启动，因为它要复用刚才那次响应的 prompt cache。
- Claude Code：`autoCompact` 策略接口即「Never waits for it」；reactive 层是 413 之后的兜底。
- Qoder：`setTimeout` 12s / 35s，超时后再检查控制位才真跑。

**本项目是唯一的例外**：`packages/ui-evolve/lib/api.js:903` 里 `summary = await deps.summariser.summarise(...)`，而 `readPanel` 是 HTTP 请求的 handler。一轮结束后的**第一次**打开面板，必然等一次模型调用，上限 `SUMMARY_TIMEOUT_MS = 20000`（`summarise.js:53`）。

这不是「学谁」的问题，是**一个 UI 请求不应该有一次模型调用的延迟**。这是定稿方案里优先级最高的一项。

**结论二：都做输出卫生，但没有一家敢相信模型的裸输出。**

Qoder 在 `jhx()` 里串了五步清洗，OpenCode 在模板没被填满时补一条 `NUDGE` 再试，Claude Code 让模型先写 `<analysis>` 再写 `<summary>`、注入时由 `formatCompactSummary()` 把 `<analysis>` 剥掉。

共同判断：**「提示词禁止」是概率性的，「代码清洗」才是确定性的。** 我们的 `INSTRUCTION` 写了「Do not use bullet points」，但**没禁前言**，也**没有任何代码清洗**（`summarise.js:539` 只有 `text.trim().slice(0, MAX_SUMMARY_CHARS)`）。

## 三、定稿方案

按「性价比 × 施工顺序」排列。P0/P1/P3 是小时级，P2 是唯一的日级改动。

### P0 · 失败文案中文化（约半小时）

**为什么做。** `summary.reason` 是写给开发者看的英文诊断，现在被 `client.js:2131-2135` 当成摘要正文渲染。用户看到的是 `the summary call timed out`、`no model route is available`。

这不是本项目独有的粗糙——Qoder 专门定义了 7 个错误码（`not_pending` / `expired` / `hash_invalidated` / `unavailable` / `start_failed` / `disabled` / `save_failed`），每个都有中文文案，另配一句 `bulkFailed:"部分建议未能处理。{{reason}}"` 做兜底。OpenCode 用 `error.type` 分类而不是抛自然语言。**共同点：内部细分类，对外稳定文案。**

**怎么做。**

在 `client.js` 里加一张映射表，未知 `reason` 一律落到「暂无摘要」，英文原文放进 `title` 供排查：

| `reason` | 对外文案 |
| --- | --- |
| `turned off` / `turned off in settings` | 摘要已在设置里关闭 |
| `no completed turn yet` | 还没有结束的回合 |
| `the turn left nothing to summarise` | 这一轮没有留下可总结的内容 |
| `no model service available` | 没有可用的模型服务 |
| `no model route is available` | 没有可用的模型线路 |
| `the model call failed: …` | 模型调用失败 |
| `the summary call failed: …` | 摘要请求失败 |
| `the model returned nothing` | 模型没有返回内容 |
| `the summary call timed out` | 摘要请求超时，稍后再看 |
| `open a conversation first` | 先打开一个会话 |

**注意。** `reason` 带冒号后缀的那几条（`the model call failed: ${message}`）要用**前缀匹配**而不是全等，否则永远命中不了。

**不做的事。** 不在 server 侧翻译。`reason` 是诊断信息，翻译它会让日志失去可检索性；翻译只发生在渲染层。

### P1 · 卡片头部显示更新时间（约一小时）

**为什么做。** Qoder 的 recap 卡片头部固定一行 `recap.updatedAt`（「更新于 {{time}}」），本项目卡片里**没有任何时间信息**。一个「上一轮」的摘要如果不带时间，读者无法判断它是刚写的还是三小时前的——而摘要的价值恰恰随新鲜度衰减。

**怎么做。**

1. `summarise.js` 的成功返回加一个 `at` 字段（毫秒时间戳）。**缓存命中时必须返回缓存里存的 `at`，不是 `Date.now()`**——否则每刷新一次时间都变，这个显示就等于没有信息。
2. `api.js` 的返回体透传 `summary.at`。
3. `client.js` 卡片 head 区（现在显示「N 调用 / N 命令 / N 文件」）追加一段相对时间：`刚刚` / `5 分钟前` / `2 小时前`。

**边界。** 相对时间用 `Intl.RelativeTimeFormat` 而不是手写字符串，理由和 `summarise.js` 里 `LANGUAGE_NAMES` 那张表一样——手写的复数与语序规则在中文之外全错。

### P2 · 回合结束就预生成，别让面板等模型（约一天，**最重要**）

**为什么做。** 见 §1.3 结论一。这是三家外部实现**全部做了**、本项目**唯一没做**的一点，也是用户能直接感知的：一轮结束后点开面板，最多要等 20 秒才看到摘要。

而且这个等待里有很大一部分是**可以完全省掉的**：那一轮已经结束了，内容不会再变，没有任何理由把它推到「有人来看」的那一刻才算。

**怎么做。**

挂载点在 `packages/ui-evolve/lib/index.js:346-372`。当前结构与顺序：

```js
const ended = event?.type === 'turn/end' ? transcripts.view(agentId)?.current?.paths : undefined
transcripts.record(agentId, event)
if (event?.type === 'turn/end') {
  sessionState.rememberTurn(agentId)
  if (ended !== undefined) sessionState.rememberPaths(agentId, ended)
}
```

**顺序是硬约束，不能改**：`ended` 必须在 `record` **之前**读（`record` 会把 `current` 折进 `previous` 或直接清空），而 `previous` 必须在 `record` **之后**读——折进去之后 `previous` 才等于「刚结束的那一轮」。`index.js:363-365` 的注释记录了这处曾经读错轮次的历史。

所以在 `rememberPaths` 之后追加：

```js
if (event?.type === 'turn/end') {
  // ... existing rememberTurn / rememberPaths
  const finished = transcripts.view(agentId)?.previous
  if (finished !== undefined) summariser.warm({ agentId, snapshot: finished, sessionRoute: routeFor(agentId) })
}
```

`Summariser` 新增一个 `warm()`：条件判断 + 不 await。

```js
/**
 * Start a summary for a turn that has already finished, without waiting.
 *
 * The panel and this call share the `inflight` and cache maps, so whichever
 * arrives second pays nothing: a person who opens the panel a second after the
 * turn ended finds the call already running rather than a fresh 20-second wait.
 */
warm({ agentId, snapshot, sessionRoute }) {
  if (valueOf(this.config)?.panelSummary !== true) return
  const language = this.languages.get(agentId)
  // No language recorded yet means the panel has never been opened for this
  // session. Generating then would be spending money on a summary nobody has
  // asked to see, in a language we would have to guess — see §4 决策 1.
  if (language === undefined) return
  void this.summarise({ agentId, snapshot, sessionRoute, language }).catch(() => {})
}
```

语言从哪来：`summarise()` 每次被面板请求调用时记一笔 `this.languages.set(agentId, language)`（含 `undefined`，用 `has()` 判断「是否记录过」与「值是不是 undefined」）。这样面板第一次打开会慢，之后每一轮都是秒开。

**为什么不做定长计时器。** Qoder 用 12s/35s 的 `setTimeout`，是因为它的 recap 要在「用户可能已经走了」之后更新，且没有明确的「这一轮结束了」事件可用。**我们有 `turn/end` 事件，比计时器更准也更省**——计时器会在会话中途用户继续打字时白跑一次。

**为什么不用 deferred 队列/调度器。** 不需要。`summarise()` 内部已经有 `inflight` 去重（`summarise.js:476`）和 64 条 LRU 缓存（`summarise.js:541-547`），预生成与面板请求撞在一起时天然合并。

**风险与对策。**

| 风险 | 对策 |
| --- | --- |
| 每轮都打一次模型 = 成本翻倍 | 实际上不涨。之前是「打开面板才算」，现在变成「每轮都算」；但 `panelSummary === false` 时完全不跑，且 64 条缓存意味着同一个 turn 不会被重复计算。**净增成本等于「从未被查看过的回合」**，这正是要放弃的部分——见 §4 决策 2 |
| 会话很快、很多轮 | `MAX_SUMMARY_CHARS` 与 300 token 上限不变；单轮成本约等于一次短问答 |
| 卸载/关闭时残留 in-flight | `summarise()` 已有 `AbortController` + 20s 超时兜底 |
| 预生成抛异常影响事件管线 | `summarise()` 所有失败路径都返回对象而非抛出；外面再套 `.catch(() => {})` 双保险；且 `ctx.on` 已包在 `safe('transcript', …)` 里 |

### P3 · 提示词补一条约束 + 输出清洗（约半小时）

**为什么做。** §1.3 结论二。`INSTRUCTION` 禁了列表、禁了 "The assistant" 开头，**没禁前言**。模型很常写「Summary: 这一轮……」，400 字的上限里白白浪费几个字，而且卡片上看起来像被污染了。

**怎么做：提示词补一条。**

```
Do not write a preamble or a label such as "Summary:" — begin with the
first sentence of the summary itself.
```

**怎么做：输出清洗。** 在 `summarise.js:539` 前后加一个 `tidy(text)`：

```js
function tidy(raw) {
  let text = String(raw ?? '').trim()
  const fence = /^```[A-Za-z]*\s*\n([\s\S]*?)\n?```$/.exec(text)
  if (fence !== null) text = fence[1].trim()
  text = text.replace(/^(?:here(?:'s| is)[^:\n]*|summary|summary of the (?:turn|session))\s*:\s*/i, '')
  text = text
    .replace(/\*\*(.+?)\*\*/g, '$1')          // **粗体**
    .replace(/`([^`\n]+)`/g, '$1')             // `行内代码` → 内容
    .replace(/^#{1,6}\s+/gm, '')               // 标题记号
    .replace(/^\s*[-*+•]\s+/gm, '')            // 列表记号，保留条目内容
  return text.replace(/[ \t]+/g, ' ').replace(/\n{3,}/g, '\n\n').trim()
}
```

**这里明确不抄 Qoder 的清洗规则。** Qoder 用 `replace(/[*_`#]+/gu, "")` 一把删掉所有 `* _ ` #`，因为它输出的是纯中文散文，这些字符必然是装饰。**我们的输出可能含路径**（`INSTRUCTION` 说的是「除非它们就是重点」，也就是允许出现），一把删会吃掉 `my_file.py` 里的下划线，把 `snake_case` 全毁掉。上面那版只删**处于标记位置的**记号，`my_file.py`、`a*b`、`#123` 都原样保留。

**P4 · 结构化输出（Claude Code 的 `<analysis>` + `<summary>`）：不做。**

值得单独说明，因为这是唯一一个「外部实现做了、看起来很有道理、但我们必须拒绝」的点。

Claude Code 让模型先写 `<analysis>` 再写 `<summary>`，注入时由 `formatCompactSummary()` 剥掉分析块。**先想再写确实能提升质量**——但代价是分析块占 token，而我们的预算是 `SUMMARY_MAX_TOKENS = 300`。300 token 里让模型先自言自语，正文会被挤短甚至截断。要做的话得同步把上限提到 600，成本翻倍，换来的质量提升在一个 400 字的中文短摘要上看不出来。

**结论：不做。** 若将来 `MAX_SUMMARY_CHARS` 上调到 800 以上，这个取舍值得重算。

## 四、明确不做（八项，逐条理由）

1. **增量续写（Qoder 的 `previousRecap`）** — 那是「会话级进度条」的机制。我们的卡叫「上一轮」，语义就是单轮独立摘要。要变的是**卡片命名**（若真想要会话级视角），不是摘要机制。
2. **强制 JSON 输出** — 没有机器消费者，只多一种失败模式。
3. **`source_signature` 过期指纹** — Qoder 必须有，因为它的 recap 落库、跨重启。我们的缓存是进程内 `Map`、键含 body 哈希，结构上不存在「读了旧摘要」的可能。
4. **`prompt_version` 入库** — 同上。唯一相关的边角：改 `INSTRUCTION` 不会让进程内缓存失效（因为 `summaryKey` 哈希的是 body 而不是提示词）。但客户端 bundle 改动本身就要重启宿主，缓存随之清空，实际代价为零。**写入注释即可。**
5. **取最近 6 条消息** — Qoder 敢只取 6 条，是因为历史压在 `previousRecap` 里。我们送的是结构化摘要（工具统计 + 12 条文件 + 最后命令 + 助手原话，截 6000 字）。砍到 6 条只会更差。
6. **5 层压缩阶梯** — 我们没有上下文窗口压力，`readPanel` 的输入是 `MAX_INPUT_CHARS = 6000` 封顶的。
7. **渐变卡片 + 双层阴影** — 纯视觉。反向理由：本项目五张卡共用一套外壳（`.dsse-card`），那是「没有哪张卡自称更重要」的表达。
8. **铺满底部的展开热区** — Qoder 这么做是因为右上角有「更多操作」菜单会与整卡点击冲突。本项目整卡可点、`.dsse-clip::after` 的渐变是 `pointer-events:none` 的装饰，现有实现更好。
