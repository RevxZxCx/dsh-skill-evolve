# 20 · 产出卡的噪声、计数与降级

本文是 18/19 的追加。它回答三个问题，三个都来自同一次真实数据取证：

1. 一个 200 条的会话里，**200 条没有一条是产物**。为什么过滤没拦住？（→ A）
2. 头部写着「200 个文件」，而人一行都没写。**数字说了谎。**（→ B）
3. 存下来的路径里，有些是一周前的一次性脚本。**要不要清掉？**（→ C）

三项的取舍已由用户 m15773 定稿：**A 接受 / B 计数不计噪声 / C 降级显示**。

## 0. 取证：真实数据长什么样

读 `~/.dsh/plugin-data/skill-evolve/sessions/` 里最大的那个会话文件
（`session-09c85c1b-….json`，`turns 1`，`paths 200` —— 正好撞上 `MAX_PATHS` 上限）：

| 目录 | 条数 |
| --- | --- |
| `dsh-skill-evolve\.rv-head` | 114 |
| `dsh-skill-evolve\.tmp-test` | 62 |
| `dsh-skill-evolve\.review` | 21 |
| `dsh-skill-evolve\test` | 3 |

用 `isNoisePath` 逐条复刻判定：**200 条里只有 3 条算噪声**。用
`isUnwalkableDirectory` 复刻遍历判定：**0 条会被挡在门外**。

也就是说，两套谓词对这份数据的回答都是「一切正常」，而人一眼看过去
两个数字都荒唐。这不是过滤器写错了某个字符，是**两张表都没描述这份数据**。

`api.js` 里已经有一段同形的自省，写在 `TEMP_DIRS` 上方：早年 276 条跟踪路径里
零条被判噪声，「the filter looked broken, and was, because none of the rules above
described the data」。**同一件事发生了第二次**，只是这次的形状从「下划线脚本」
变成了「点开头的工作副本目录」。

## 1. A · 遍历侧补一张表，而不是把卡片的谓词搬过去

### 问题

`scan-changes.js:111` 的默认值是 `isUnwalkableDirectory`，它查的
`UNWALKABLE_DIRS`（`api.js:368`）是一张**精确名字**表：`node_modules`、`.git`、
`__pycache__`、`.venv`……**它不认前缀，也不认点目录的普遍形态**。

于是 `.rv-head/`、`.tmp-test/`、`.review/` 三个目录各带一千多个文件走进遍历，
吃满 `MAX_SCANNED_ENTRIES = 5000` 的预算，把真正要看的文件挤出去。

### 改法

在 `api.js` 里新增两个模块级常量，并把 `isUnwalkableDirectory` 改成三段判断：

```
UNWALKABLE_DIRS         精确名字（现有表不动）
UNPRODUCTIVE_DIRS       新增：确定不装产物的点目录（.tmp-test、.review、.cover、.nyc_output …）
UNPRODUCTIVE_PREFIXES   新增：工作副本前缀（.rv-、.audit-、.tmp-、.probe-、.scratch-）
```

### 为什么不是「把 `isNoisePath` 整张表搬给遍历」

这是 S8 已经付过一次学费的地方，代码里留着当时的注释（`api.js:354-367`）：

> 用 `dist`/`build`/`out`/`target`/`coverage` 剪枝后，走查在一个真实仓库上只返回
> 了四个文件，而真正要紧的两个连 `check-ignore` 都没问到 —— **为补 git 盲区而加的
> 那条通路，在同一个地方也瞎了**。

`isNoisePath` 回答的是「读者想不想看到这一行」，`out/` 在里面是噪声；
遍历回答的是「这一轮产出的东西可能不在里面」，`out/` 在里面**恰恰是最可能的地方**。
两个问题共用一个函数，就是 S8 的 bug。所以 A 只补「确定不装产物」的那一类，
`out`/`dist`/`build` 继续可遍历。

### 被否决的方案

- **把 `scratchName` 套到目录上**（凡是 `_` 开头的目录都剪）：会剪掉 Jekyll 的
  `_posts`/`_layouts`/`_data` 和 Hugo 的 `_build`，全是源码。`isGeneratedDirectory`
  的注释里已经写过这条，不能在遍历侧重新犯。
- **遍历时不做任何剪枝，靠 `maxEntries` 兜底**：实测就是这个状态，结果是 5000 条
  预算被三个目录吃光，`coverage` 恒为 `partial`，**每一轮都报「目录没读完」**。
- **给 `.rv-`/`.tmp-` 这类前缀加进卡片的噪声谓词**：**这一条我最初否决过，理由是错的，已改。**
  初稿写的是「归到『生成文件』是一次新的误标，卡片侧不改，历史数据由 B 和 C 处理」。
  实测推翻了它：改之前 `.rv-head` 的 `card-noise=false`，也就是说那 200 条历史路径
  在卡片侧**仍算人写的**，B 的「计数不计噪声」对它们完全无效 —— 数字还是 200，
  而我却把「由 B 处理」当成不改卡片的理由，这是自相矛盾。

  正确的分工是：**卡片侧比遍历侧宽，且共享同一张表。** 遍历只排除确定不装产物的；
  卡片还要把 `out`/`dist`/`build` 算作机器产物。两个问题不同，回答可以不同，
  但**关于同一批目录（工作副本）必须一致**，否则读者会看到「走查跳过了它，
  卡片却说这是你写的」。所以 `UNPRODUCTIVE_DIRS`/`UNPRODUCTIVE_PREFIXES`
  两个谓词共用。

## 2. B · 头部数字只数人的文件，另用灰字说清楚还有什么

### 问题

`client.js:2459`：

```js
const fileMeta = `${ordered.length} 个文件`
```

`ordered` 是**全部**行，含噪声。所以卡片顶上写着「200 个文件」，
而其中 200 条全部落在 `.rv-*` 与 `.tmp-*` 里。用户看到的就是这个数字。

### 改法

头部拆成**一个主数字 + 最多两句灰字**：

```
3 个文件                          ← N：人写的、且没过期的
· 200 个生成文件                   ← M：noise === true（主数字为空时去掉「另有」）
· 12 个较早                        ← K：过期的（见 C）
```

**算术必须闭合**，这是这一节唯一硬性要求：

```
屏幕上实际画出的行数 + 徽标余数 = N + M + K = ordered.length
```

这条契约在 S2 的真机验收里已经建立过一次（当时是 `200 = 4 + 196`），
改成两段数字之后必须仍然成立 —— 否则读者会用头部去核对徽标，然后发现对不上。
折叠态画的是 `current` 里的行，徽标余数因此从 `ordered.length` 算，
不是从 `N` 算。

### 被否决的方案

- **保持 `ordered.length`，只把噪声排到最底**：这就是现状，用户的原话是
  「目前产出会显示很多实际没用的东西」，数字本身就是其中一部分。
- **头部只写「N 个文件」，不写灰字**：折叠态只看得到 4 行，读者会以为
  剩下 196 行不存在。灰字的作用是让「还有东西」这件事**在展开之前就说出来**。
- **把灰字做成 tooltip 而不是可见文本**：屏幕阅读器读不到，且这个数字是
  「我的产出去哪了」的直接答案，不该藏在悬停后面。

## 3. C · 过期的路径降级显示，不删除

### 问题

`session-state.js` 存的每条路径都带 `at`（`readPathEntry` 已经读它，
`rememberPaths:728` 用注入的时钟写它，重新记录会刷新）。它今天没有任何读者。

### 改法

在 `api.js` 的 `statTouchedFiles` 里算一个布尔值，随 payload 一起下去：

```js
stale: at !== null && now - at > STALE_AFTER_MS
```

- 判据常数 `STALE_AFTER_MS` 放在 `api.js`，**只有一个定义处**。
- `now` 从调用方注入（与 `statTouchedFiles` 已有的 `readStat` 同一手法），
  测试才能不依赖真实时钟。
- 客户端拿到 `stale === true` 的行：不删、不藏，**归到单独一组、名字褪色**，
  且**不计入 N**（但计入 K，所以算术仍然闭合）。

### 为什么是降级而不是删除

产出是**记录**，不是缓存。删掉之后「这一轮做了什么」永久缺一块，而这个项目
反复立过同一条规矩：`missing` 的文件要留在卡上带删除线（S1 的三态），
`coverage: none` 要如实说「我没看」而不是说「干净」（S7）。

Qoder 做得更绝：它的 `turn_file_change_files` 一行不删，清理只有三条，全是结构性的
（blob 按引用计数回收、会话删除时级联、外键 `ON DELETE CASCADE`），**没有一条按时间**。
`retention_score`/`enforceRetention`/`purgeExpired` 这些看着像的名字，解码上下文后
全属于记忆系统与 profile/进程记录回收，`turn_file_change_*` 一个都不在里面。

它宁可给一张 `turn_file_change_unsupported` 表记 `reason`（`binary_file`、
`path_unavailable`、`snapshot_failed`……），也不猜「这个没用所以不记」。
**记不全就记录为什么没记全** —— 这条比它的任何阈值都更值得抄。

### 阈值的诚实说明

`STALE_AFTER_MS` 取 **7 天**，是估的，不是标定的。理由是：一个仍在进行中的会话，
`at` 会随每次重记刷新；连续七天没被再次碰过的路径，要么是一次性脚本，
要么是会话已经停了。**这个数字会在真机验收里被记录，将来有真实分布再改。**

### 被否决的方案

- **物理删除**（用户提过「清理一些长时间没有修改的」）：见上，且 `trimPaths`
  已经在 `MAX_PATHS` 压力下按 `seq` 淘汰最旧的，硬删除的边际收益接近零。
- **按文件系统 `mtime` 判过期**：`mtime` 是文件最后一次被任何进程写的时间，
  而这里要回答的是「这个会话最后一次碰它是什么时候」。一个你没动过但
  `npm install` 碰过的文件会被判成新鲜 —— 用错了时钟。
- **让 `stale` 在客户端算**：客户端拿不到一致的 `now`，且判据会变成第二份实现。
  `isNoisePath` 的教训（表写在两处，必然静默漂移，D-125）在这里同样成立。

## 更正 2026-11-15：上文里的「197 条」是错的，真值是 200 条

这份文档的第一稿把真实会话写成「200 条里 197 条不是产物，3 条是人写的」。那个数字来自一个
在 Python 里复刻的 `isNoisePath`，它只按目录段判断，漏掉了 `scratchName` 对**文件名**的那条
规则——`_head.js`、`_probe_tail.js` 这类下划线开头的文件因此被判成人写的。

用生产模块（`_edit/_real_classify.mjs` 直接 `import statTouchedFiles`）重跑同一份数据：
**200 条全部 `noise=true`，人写 0 条**。上文所有 197 已按真值改过，这里保留一行说明它们
为什么曾经是 197，因为「复刻的谓词证明的是复刻件」这件事本身值得记（见
[`handover/03-defects.md`](./handover/03-defects.md) DEF-135）。

结论不变，而且更强了：这份会话的头部应该一个数字都没有，只有一句「200 个生成文件」。

## 更正 2026-11-16（之五）：A 的两张表都不是最强的那条规则，而最强的那条用错了对象

上面 §1 说 A 项「只补确定不装产物的目录」。这个判断没错，但它漏了一件事：
卡片侧还有一条比它更激进的规则，一直在生效，而且被用在了不该用的对象上。

`packages/ui-evolve/lib/api.js` 的 `isNoisePath` 里，判定了**祖先目录**的那一段
把 `scratchName` 也算了进去，而 `scratchName` 含一条 `segment.startsWith('_')`。
这条规则是为**文件名**写的（`_slot_probe.mjs` 确实是临时文件），
问到目录就把 `_prototype/`（用户正在看的原型）、`_posts/`/`_layouts/`（Jekyll）、
`_build/`（Hugo）整棵判成生成产物。

**这条理由文档里早就有了。** `isUnwalkableDirectory` 的注释原文：

> `scratchName` is deliberately NOT applied here: its leading-underscore rule was
> written for scratch FILES, and on directories it would prune `_posts`/`_layouts`/`_data`
> in every Jekyll site and `_build` in Hugo — all source.

遍历侧照着它做了，卡片侧漏了同步。所以这不是「门限设得太严」，
是两套谓词分家时漏掉的一半，而没有任何断言在检查它们在目录上是否回答一致。

两处一起改：

- **`scratchDirectory = (segment) => TEMP_DIRS.has(segment)`**：目录只认 `tmp/`、`.probe/` 这一类；
  文件名仍走 `scratchName`。影响面实测 43 个会话 536 条路径，59 条的生成身份完全依赖祖先下划线。
- **`filesOpen` 从布尔改成三态 `null`**：`null` = 读者没碰过徽标。零人写的会话折叠列表是空的，
  卡片需要在「另一种选择是一行都不显示」时自己展开，而读者点过之后不再抢回来。
  灰字同时换措辞：不再说「另有 N 个生成文件」（「另有」指向一个不存在的主数字），
  改说「全部 N 个文件都是生成文件」。

真机复核（用户报的那份会话 `session-b5ee3f88`）：25 条路径 → **人写 14 / 生成 11**，
头部回到「14 个文件」，`_prototype/` 下十四个全部成行，九个探针脚本仍归生成文件。
3863 断言全绿，四套突变 195/45/69/128 全杀。

**这条更正对着 §0 的那份真实数据**：当时 200 条里 200 条判生成，结论是「谓词一条都没描述这份数据」。
现在多了一条同样成立、方向相反的结论 —— **谓词也可能描述得过头，而过头的那一半同样没人量**。
