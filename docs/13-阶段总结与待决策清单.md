## 二、四条已经确定的结论

### 结论 1：Qoder 的「产出」不是卡片，是面板的一个分组

`artifact` 只是 13 个分组之一。分组里的每一条都走同一个**通用行模型** `q41`：

```js
{ id, kind, origin, label, detail, target, messageId, toolUseId, evidenceId, turnId, specArtifact, planPreview, timestamp }
```

`kind` 有五种：`artifact` / `browser` / `runtime` / `source` / `memory`。`target.type` 有四种：`file` / `url` / `message` / `evidence`。

**这个统一是整套 UI 的地基。** 连「技能自进化建议」都是被临时包装成 `kind:"runtime"` 的行塞进去的（`sD1`），省掉了一整套专用 UI。

### 结论 2：产出物在 Qoder 里有生命周期，本项目只有路径

| 维度 | Qoder | 本项目 |
| --- | --- | --- |
| 身份 | `artifactId = hash(path + "\0" + size)`，即**内容身份** | 文件路径字符串 |
| 存活 | `artifactFileStatusService` 四态 `checking` / `available` / `missing` / `invalid`，80ms 合批、最多 4 并发、订阅 `onWorkspaceFileChanged`、focus 时全量 invalidate | `stat` 失败即静默丢弃（`api.js:443-446`） |
| 预览 | 独立一等概念，四态渲染器（thumbnail / document / spreadsheet / unavailable） | 无，只有 `openResource` 跳侧栏 |
| 打开方式 | 六种，按文件类型与设置决定，且**按路径持久化**（`artifactFileOpenModes`） | 一种（`sidebarRight.openResource`） |
| 过期守卫 | 存在 | 无 |

**这是本项目与原型之间最大的实质差距**，不是确认流程，是产出物有没有状态。

### 结论 3：Qoder 的「采纳」产物是新会话，不是 skill 文件

```js
if (result.sessionId) {
  this.navigation.push({ kind: "chatSession", sessionId: result.sessionId, surface: "conversation" })
}
```

全部文案印证：`create` / `update` / `createSuggestion` / `createAll` 中英文**都是「创建任务」**，`create` 与 `update` 中文完全相同。

**本项目采纳 = 直接写文件**（`staged` 时才等模型写定稿）。抄「开新会话」等于砍掉自己更强的能力。

### 结论 4：本项目的候选生命周期比 Qoder 完整

| | Qoder | 本项目 |
| --- | --- | --- |
| 候选队列 | **没有本地文件**（`skill-usage.json` 只有 `usageCount` / `lastUsedAt`） | `maxCandidates` 50 |
| 过期 | 运行期错误码 `expired` | `candidateTtlDays` 30 |
| stale 中间态 | 无 | `staleAfterDays` 90，`/skill-review` 分 live / stalled 展示，stalled「可读不可批」 |
| 晋升与反转 | 无 | `promoteAfterUses` 3 / `invertAfterHarmful` 3 |

**所以「拙劣模仿」这句话要分开看**：UI 结构层面确实是模仿且不够；业务逻辑层面不是模仿，某些地方比原型更细致。

## 四、明确不做的（附理由，防止被「Qoder 有啊」拉回讨论）

| 项 | 理由 |
| --- | --- |
| **三种容器形态** | 本项目面板在 `shell.overlay`（`inset:0; pointer-events:none`），DSH 没有「固定右栏」宿主槽位。硬做是自造布局，会和宿主的侧栏抢空间 |
| **六种打开方式** | DSH 只有 `sidebarRight.openResource` 一个入口（`client.js:2796`）。做六种就是造假动作 |
| **悬停预览** | 需要 office/pdf 渲染管线，宿主不提供 |
| **HTML 消毒 + CSP 沙箱** | 没有 iframe 预览场景，这套安全处理没有落点 |
| **Figma embed** | 同上，且是 Qoder 的特定集成 |
| **采纳 = 开新会话** | 本项目采纳是直接写文件，能力更强 |
| **建议由主进程生成** | 本项目没有主进程；候选只能由模型在会话里提交 |
| **`origin: automatic/manual` 字段** | Qoder 用它区分「自动记录」和「用户手动添加的来源」，本项目没有「手动添加产出」这个功能 |

## 五、待用户决策（三项，来自 10）

1. **P0 的删除线文件要不要进折叠态？**
   建议不进（折叠态回答「这轮做了什么」），代价是要展开才看得到删除。若认为「文件被删要立刻看得见」更重要则进，代价是折叠态可能四个全是删除线。

2. **P1（`turnId`）做不做？**
   唯一需要改状态文件格式的改动，唯一能让折叠态跨重启准确的。产出卡若非高频使用可跳过。

3. **要不要只做 P0 + P2？**
   两条合计半天，覆盖用户能直接感知的全部差异。P1 是长线投入。
