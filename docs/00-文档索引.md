# 00 · 文档索引

本仓库的文档分五层：**AI 自动入口**是根 [`AGENTS.md`](../AGENTS.md)，**活操作手册**是 [`27-开发与集成手册.md`](./27-开发与集成手册.md) 与 [`28-性能审查手册.md`](./28-性能审查手册.md)，**进行中任务单**在 [`tasks/`](./tasks/README.md)，**产品说明**在各包的 `README.md`，**历史论证与冻结台账**在 `docs/01`–`26`、`29` 与 `handover/`。

## 新会话先读什么（按顺序，不要跳）

1. **[`AGENTS.md`](../AGENTS.md)** —— AI 自动冷启动薄入口（红线、门禁命令、文档路由）。
2. **[`handover/ACTIVE-STATE.md`](./handover/ACTIVE-STATE.md)** —— 自动生成的活跃视图（最新基线、进行中任务单、待闭环真机验收项）。
3. **[`27-开发与集成手册.md`](./27-开发与集成手册.md)** —— 唯一权威操作手册：怎么装进宿主、一次改动走哪十步、哪些数字不能碰。**读它之前不要改任何代码。**
4. **[`28-性能审查手册.md`](./28-性能审查手册.md)** —— 七条性能预算、三层测量输入、什么时候必须量；命令是 `node scripts/perf-budget.mjs`。
5. 下面的「按目的进入」，决定下一步读哪个包或哪份历史文档。

`handover/` 遵循**只增不改**铁律：旧的四份单文件台账（`01`–`04`）已原地冻结为只读历史，**不要从头读**；新增交接条目写入 `handover/entries/` 并运行 `npm run handover:build` 刷新活跃视图（详见 [`handover/index.md`](./handover/index.md)）。

### 关于旧路径

`02`、`05`、`06`、`07` 写在拆包之前，里面的模块路径是 `lib/index.js`、`lib/client.js` 这一类。**它们不改写**，避免伪造历史。对照关系：

| 文档里的旧路径 | 现在的位置 |
| --- | --- |
| `lib/api.js` `lib/client.js` `lib/gutter.js` `lib/summarise.js` `lib/transcript.js` | `packages/ui-evolve/lib/` |
| `lib/candidates.js` `lib/evidence.js` `lib/lifecycle.js` `lib/outcome.js` `lib/paths.js` `lib/skillfile.js` `lib/store.js` | `packages/core/lib/` |
| 其余 `lib/*.js` | `packages/skill-evolve/lib/` |
| 路由 `/api/skill-evolve` | `/api/ui-evolve` |

读 `05` 时特别注意：它按「单包插件」描述结构，现在是两个插件通过 `skillEvolve` 服务连接；**第二十六章（真实浏览器验收）之后的内容仍然准确**。

## 按目的进入

- **我要接手这个仓库 / 多 Agent 交接** → 先读根 [`AGENTS.md`](../AGENTS.md) 与 [`handover/ACTIVE-STATE.md`](./handover/ACTIVE-STATE.md)，若属于协作任务读 [`tasks/`](./tasks/README.md)，再读 [`27-开发与集成手册.md`](./27-开发与集成手册.md)。
- **我要加一个新功能（不是修一个 bug）** → [`27-开发与集成手册.md`](./27-开发与集成手册.md) 的 §7，先答四个问题，再按注册点表列出本次要碰的每一处。
- **我想安装 / 使用 / 查配置键** → 根 [`README.md`](../README.md)，然后对应包的 `README.md`。
- **我要改检测逻辑、工具或命令** → [`packages/skill-evolve/README.md`](../packages/skill-evolve/README.md)，必要时回查 `docs/05`。
- **我要改面板、卡片或提示词建议** → [`packages/ui-evolve/README.md`](../packages/ui-evolve/README.md)；几何改动先读 `handover/03-defects.md` 的 DEF-25/26/27/28。
- **我要知道某个决定为什么这么定** → 先看 [`handover/ACTIVE-DECISIONS.md`](./handover/ACTIVE-DECISIONS.md)，历史决策查 `handover/02-decisions.md`。
- **我要知道某段代码为什么长这样** → 查 `handover/entries/` 与冻结的 `handover/03-defects.md`（重点看「为什么测试没抓到」）。

## 维护规矩

1. **`docs/01`–`26`、`29` 是历史，不改写。** 结论失效时在 `handover/entries/` 追加更正条目并指回原文。
2. **`handover/` 只增不改。** 旧的 `01`–`04` 原地冻结；新条目一律在 `handover/entries/` 新建独立文件并运行 `npm run handover:build` 刷新活跃视图（D-255）。
3. **包的 `README.md` 跟着包走。** 配置键只在各包 README 里维护，不在根 README 重复列。
4. **新增编号文档时，同步更新本文件清单表，且状态栏保持一句话。** 严禁把多轮流水塞进索引单元格。
5. **流程只写在 `27`，性能预算只写在 `28`。** 改流程或预算就改 `27`/`28`，不写第二份。
6. **`AGENTS.md`、`27`、`28` 是「现状」，可以就地改写。** 改写时保留关键数字的日期与机器环境。
7. **加新功能先答 `27` §7 四问、列注册点、建任务单（若跨 Agent），最后才写代码。**
