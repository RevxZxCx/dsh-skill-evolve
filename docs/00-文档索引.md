# 00 · 文档索引

本仓库的文档分三层：**产品说明**在各包的 `README.md`，**仓库总览与文档导航**是本文件，**论证与历史**在 `docs/` 的编号文档里。

改代码前先读哪一份，取决于你要做什么——见下面的「按目的进入」。

```
README.md                    套件总览：四包是什么、为什么分开、怎么装

```

### 关于旧路径

`02`、`05`、`06`、`07` 写在拆包之前，里面的模块路径是 `lib/index.js`、
`lib/client.js` 这一类。**它们没有被改写，也不应该被改写**——那几份文档记录的是
当时的事实，把路径批量替换成新位置会伪造一个从未存在过的历史，还会让审查意见
读起来像是对着现在的代码写的。

对照关系：

| 文档里的旧路径 | 现在的位置 |
| --- | --- |
| `lib/api.js` `lib/client.js` `lib/gutter.js` `lib/summarise.js` `lib/transcript.js` | `packages/ui-evolve/lib/` |
| `lib/candidates.js` `lib/evidence.js` `lib/lifecycle.js` `lib/outcome.js` `lib/paths.js` `lib/skillfile.js` `lib/store.js` | `packages/core/lib/` |
| 其余 `lib/*.js` | `packages/skill-evolve/lib/` |
| 路由 `/api/skill-evolve` | `/api/ui-evolve` |

读 `05` 时特别注意：它按「单包插件」描述结构，其中「一个 `apply()` 里同时装检测
器和面板」已经不成立，现在是两个插件通过 `skillEvolve` 服务连接。**第二十六章
（真实浏览器验收）之后的内容仍然准确**，因为它讲的是几何与主题 token，与包边界无关。

## 按目的进入

**我想安装/使用** → 根 `README.md`，然后对应包的 `README.md`（配置键在各包自己的 README 里）。

**我要改检测逻辑、工具或命令** → `packages/skill-evolve/README.md`，再看
`docs/05` 的相应章节；交接口径看 `handover/01-status.md`。

**我要改面板或卡片** → `packages/ui-evolve/README.md`；几何层改动必须先读
`handover/03-defects.md` 里 DEF-25/26/27/28（裁剪、token、高度、渐隐），那四条都是
只有真实浏览器能抓到的类型。

**我要接手这个仓库** → `handover/index.md` 给的顺序：`01-status` → `02-decisions` →
`03-defects` → `04-reviews`，然后按需回查 `docs/`。

**我要知道某个决定为什么这么定** → `handover/02-decisions.md` 的 D-01…D-20，每条都写了被否决的替代方案。条文之外的论证回查 `docs/05`。

**我要知道某段代码为什么长这样** → `handover/03-defects.md`，16+ 个缺陷每条都写了「为什么测试没抓到」。这一栏比修法本身更值钱。

## 维护规矩

1. **`docs/01`–`08` 是历史，不改写。** 发现其中某条结论已失效，在
   `handover/` 里追加一条更正，并指回原文，不要编辑原文。
2. **`handover/` 只增不改。** 写错了就再追加一条更正，不回头改。这条是用户
   （m20052）明确定的规矩，理由是一份可以被悄悄修改的记录无法用于追责。
3. **包的 `README.md` 跟着包走。** 配置键拆到两个包里了，就不要在根 README 重复
   列一遍——重复的那份会先过期。
4. **新增一份编号文档时，同时更新本文件的清单表。** 表格里的「状态」栏是这份
   索引存在的主要理由：读者需要知道哪份能信。
