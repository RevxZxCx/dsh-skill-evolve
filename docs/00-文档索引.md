# 00 · 文档索引

本仓库的文档分四层：**入口手册**是 [`27-开发与集成手册.md`](./27-开发与集成手册.md)，**产品说明**在各包的 `README.md`，**仓库总览与文档导航**是本文件，**论证与历史**在 `docs/` 的编号文档里。

## 新会话先读什么（按顺序，不要跳）

1. **[`27-开发与集成手册.md`](./27-开发与集成手册.md)** —— 唯一入口。怎么装进宿主、一次改动走哪十步、哪些数字不能碰。**读它之前不要改任何代码。**
2. **[`28-性能审查手册.md`](./28-性能审查手册.md)** —— 七条性能预算、三层测量输入、什么时候必须量；命令是 `node scripts/perf-budget.mjs`。
3. 下面的「按目的进入」，决定下一步读哪个包或哪份历史文档。

`handover/` 那四份是流水记录（只增不改），**不要从头读**；接手顺序见 [`handover/index.md`](./handover/index.md) 的「怎么用」一节。

`lib/client.js` 这一类。**它们没有被改写，也不应该被改写**——那几份文档记录的是
当时的事实，把路径批量替换成新位置会伪造一个从未存在过的历史，还会让审查意见
读起来像是对着现在的代码写的。

## 按目的进入

**我要加一个新功能（不是修一个 bug）** → [`27-开发与集成手册.md`](./27-开发与集成手册.md) 的 §7，先回答那四个问题，再照着注册点表列出这次要碰的每一处；漏一处不会报错，只会让功能「有时候不生效」。

**我想安装/使用** → 根 `README.md`，然后对应包的 `README.md`（配置键在各包自己的 README 里）。

**我要改检测逻辑、工具或命令** → `packages/skill-evolve/README.md`，再看
`docs/05` 的相应章节；交接口径看 `handover/01-status.md`。

**我要改面板或卡片** → `packages/ui-evolve/README.md`；几何层改动必须先读
`handover/03-defects.md` 里 DEF-25/26/27/28（裁剪、token、高度、渐隐），那四条都是
只有真实浏览器能抓到的类型。

**我要接手这个仓库，或第一次在这个仓库里改代码** → 先 [`27-开发与集成手册.md`](./27-开发与集成手册.md)
（流程与约束），再 [`28-性能审查手册.md`](./28-性能审查手册.md)（预算），最后才按
`handover/index.md` 的顺序读 `01-status` → `02-decisions` → `03-defects` → `04-reviews`。

**我要知道某个决定为什么这么定** → `handover/02-decisions.md` 的 D-01…D-20，每条都写了被否决的替代方案。条文之外的论证回查 `docs/05`。

**我要知道某段代码为什么长这样** → `handover/03-defects.md`，16+ 个缺陷每条都写了「为什么测试没抓到」。这一栏比修法本身更值钱。

## 维护规矩

1. **`docs/01`–`08` 是历史，不改写。** 发现其中某条结论已失效，在
   `handover/` 里追加一条更正，并指回原文，不要编辑原文。
2. **`handover/` 只增不改。** 写错了就再追加一条更正，不回头改。这条是用户
   （m20052）明确定的规矩，理由是一份可以被悄悄修改的记录无法用于追责。
3. **包的 `README.md` 跟着包走。** 配置键拆到两个包里了，就不要在根 README 重复
   列一遍——重复的那份会先过期。
4. **新增一份编号文档时，同时更新本文件的清单表。** 表格里的「状态」栏是这份
   索引存在的主要理由：读者需要知道哪份能信。
5. **流程只写在 `27`，性能预算只写在 `28`。** 包的 README 与 `handover/` 的追加段不重复这两件事——
   重复的那份会先过期（DEF-187 就是 README 还在讲已删掉的四个采集器）。改了流程或预算，
   就改 `27`/`28` 与它们的索引行。
6. **`27`/`28` 是「现状」，可以就地改写。** 历史文档的只增不改规矩不适用于这两份：
   它们回答「现在要做什么」，写成流水就没人读了。改写时保留每次数字的日期与机器，
   否则下一个读者无法判断那个数是今天的还是去年的。

7. **加一个新功能时，先回答问题、再列注册点，最后才写代码。** 判据在 `27` §7：这一次碰的是十一族注册点里的哪几族，逐族写进那次改动说明。要不要先写一份方案文档，判据只有 `27` §7 那一张单子（判据不写第二份：两处各写一半时，谁都不全），这条不是流程仪式，是因为「漏掉一个注册点」在这四包里从不报错——它只会让功能看起来偶尔不工作。
