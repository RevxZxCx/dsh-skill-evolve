## 一句话结论

Qoder 的「侧栏」不是一个侧栏，而是**同一个面板主体的三种容器形态**（浮层 / 钉住的浮层 / 固定右栏），主体本身是一组**按可见性开关逐项门控的分组**，分组里的条目共用一种**泛化的行模型**——产出、网页查阅、技能与 MCP、来源、记忆、视频、目标、侧会话、后台 Agent、后台进程、快速笔记、演示、计划文件，全是同一种行。

**这三件事决定了它和本项目的形态差异**：形态可切换、分组可增删、行模型统一。而本项目的面板是「三张写死的卡片 + 一张候选审核卡 + 一张设置卡」，卡片之间没有共同的行模型。

## 一、三种容器形态

面板主体（`x$`）本身不知道自己被放在哪，容器决定它长什么样。`displayMode` 只有两个值：`"fixed"`、`"floating"`。

### 1.1 浮动 popover（默认）

组件 `Pw0`，Radix Popover：

| 属性 | 值 |
| --- | --- |
| `align` | `"end"` |
| `sideOffset` | `8` |
| `collisionPadding` | `8` |
| `surface` | `"solid"` |
| `className` | `w-[280px] max-w-[calc(100vw-16px)] overflow-hidden p-0` |
| `aria-label` | `chatSession.highlights.title`（「任务监控」） |

触发器是一个 ghost 图标按钮（`ON`，`size=16`），带 `data-task-monitor-trigger`、`aria-expanded={pinned || open}`；打开时加 `!bg-fill-tertiary`；tooltip 文案 `chatSession.highlights.open`（「打开任务监控」）。

**注意一个细节**：popover 的 `open` 是 `G ? !1 : q` —— **钉住时强制不打开 popover**，因为此时渲染的是另一个容器。两者互斥，不是叠加。

### 1.2 钉住的浮层（pinned）

```jsx
<div
  ref={pinnedPanelRef}
  className="fixed z-[1000] w-[280px] max-w-[calc(100vw-16px)] overflow-hidden
             rounded-lg border border-border-tertiary bg-bg-container text-sm text-text
             shadow-lg [-webkit-app-region:no-drag]"
  style={positionStyle}
  aria-label="任务监控"
  data-task-monitor-pinned-panel
>
```

**`pin` 不等于「收进右侧栏」。** 它只是把一个浮层从 Radix 的定位系统里摘出来，改成 `position: fixed` + 绝对坐标，从而可以拖。真正的右侧栏是第三种形态。

`[-webkit-app-region:no-drag]` 是必须的：Qoder 窗口顶部有可拖拽区，不写这一条，拖面板就会拖窗口。

### 1.3 固定右栏（fixed）

组件 `kD1`：

```jsx
<div className="flex h-full min-h-0 flex-col bg-bg-layout text-sm text-text"
     aria-label="任务监控" data-task-monitor-fixed-panel>
  <div className="min-h-0 flex-1">
    <Panel displayMode="fixed" onClose={() => {}} />
  </div>
</div>
```

三个可读出的设计意图：

- `h-full min-h-0` + 内层 `min-h-0 flex-1` —— 这是 flex 容器里嵌滚动区的标准写法，`min-h-0` 缺一个，滚动就会失效、内容把容器撑破。
- `onClose: () => {}` —— 固定右栏没有关闭按钮，关它等于关掉整个侧栏，所以传一个空函数。
- `displayMode="fixed"` 会让主体把 `maxHeight` 放开（`fixed` 时为 `void 0`，`floating` 时为 `524`），padding 也换一套（`h-full min-h-0 px-3 pb-3 pt-2` vs `p-3`）。

### 1.4 `displayMode` 影响到的所有地方

| 位置 | `fixed` | `floating` |
| --- | --- | --- |
| 主体最大高度 | `void 0`（不限） | `524` |
| 主体 padding | `h-full min-h-0 px-3 pb-3 pt-2` | `p-3` |
| 元信息行（`pl1`/`Xz`） | 显示 label 文字 | 只留 tooltip + `sr-only` |
| 计划文件卡标题色 | `text-text` | `text-text-secondary` |

这是「窄容器少显示」的典型做法：**同一份数据，窄的时候靠 tooltip 补，宽的时候直接铺开。**

## 二、钉住与拖拽：`Iv0(sessionId, store)`

这是整个面板里最值得看的一段逻辑，因为它用**一个状态表达了两件事**。

### 2.1 pinned 的判据是「有没有位置」

```js
const [open, setOpen] = useState(false)
const [position, setPosition] = useState(() => {
  const saved = store.get(sessionId)
  return saved ? clamp(saved, null) : null
})
const pinned = position !== null
```

没有 `isPinned` 布尔量。**有坐标 = 钉住**。这一条把所有「钉住但没拖动过」「取消钉住」「窗口 resize 后重新夹取」的分支合并成了一个状态。

### 2.2 常量

```js
eD1 = 280   // 面板宽度
Mv0 = 560   // 面板参考高度
tD1 = 96    // 最小可视高度
z8  = 16    // 视口边距
```

### 2.3 四个动作

**`pinPanel`**：取触发器按钮的 `getBoundingClientRect()`，把面板放在触发器位置；没有则回落 `{ x: window.innerWidth - 280 - 16, y: 48 }`。夹取后 `store.set(sessionId, position)`，并 `setOpen(false)` 关掉 popover。

**`unpinPanel`**：`setPosition(null)` + `store.set(sessionId, null)`。

**`startDrag`**：第一行是守卫——

```js
if (!pinned || event.target.closest('button,input,a,textarea')) return
```

**拖拽区域排除所有交互元素。** 缺这一条，用户想点面板里的按钮，手指微动就成了拖动。

然后 `setPointerCapture` 抓住指针，记录 `{ pointerId, offsetX: clientX - rect.left, offsetY: clientY - rect.top }` —— 记的是**指针相对面板左上角的偏移**，不是「上次位置 + delta」。前者在拖动过程中不会累积误差。

**`resize` 处理**：窗口尺寸变化时用当前坐标重新夹取一次。**这是防止面板掉到屏幕外唯一有效的办法**——把窗口从 1920 缩到 1280，右边缘那个面板如果不管，就会永久消失在可视区外。

### 2.4 夹取函数 `oq`

```js
function oq(p, el) {
  const w = Math.min(el?.offsetWidth  ?? 280, window.innerWidth  - 16 * 2)
  const h = Math.min(el?.offsetHeight ?? 560, 96, window.innerHeight - 16 * 2)
  return {
    x: Math.min(Math.max(p.x, 16), Math.max(16, window.innerWidth  - w - 16)),
    y: Math.min(Math.max(p.y, 16), Math.max(16, window.innerHeight - h - 16))
  }
}
```

两处值得注意：

1. **`Math.max(16, ...)` 兜底**：窗口比面板还窄时，上界会小于下界 `16`，`Math.min(Math.max(x,16), 更小的数)` 会算出越界值。加一层 `Math.max(16, ·)` 保证上界永远不小于 16。
2. **`Math.min(offsetHeight, 96, ...)`**：高度上限取「面板实际高度、最小可视高度 96、视口减边距」三者最小 —— 意思是**至少要露出 96px**，而不是要求整个面板可见。

### 2.5 位置存储 `K_1`

```js
const R60 = 50
class K_1 {
  positions = new Map()
  get(key) {                       // 命中即「触摸」，移到 LRU 尾
    const v = this.positions.get(key)
    return v ? (this.positions.delete(key), this.positions.set(key, v), v) : null
  }
  set(key, value) {
    this.positions.delete(key)
    if (value) {
      this.positions.set(key, { x: value.x, y: value.y })
      if (this.positions.size > R60) this.positions.delete(this.positions.keys().next().value)
    }
  }
}
```

**LRU 上限 50 个会话**，`get` 时刷新顺序（所以常看的那几个会话的位置不会被挤掉）。

它挂在 `workbenchStateService`（`B3 = n0("workbenchStateService")`）的 `taskMonitorPresentationStore` 上。**但 `K_1` 只是内存**，真正落盘靠同一服务上的 `persistWorkbenchUiState()`，写到 `"loop.workbench-ui.v1"` 这个键。同一个服务里还存着 `productModeValue`、`reviewDiffView`、`workspaceSessions`、`openTerminalSessions`、`chatActivityExpansions`、`sidebarDeviceSectionOrderValue`、`artifactFileOpenModeStore` 等。

**这里有一个设计取舍值得记下**：位置存内存 LRU、靠统一的 `persistWorkbenchUiState` 批量落盘，而不是每次拖动结束写一次文件。拖动过程中 `pointerup` 才 `set`，`set` 只改内存，落盘由工作台状态的统一机制负责。

## 三、分组可见性

### 3.1 十三个分组

```js
PN1 = ["recap","goal","spec","backgroundAgents","backgroundProcesses",
       "sideChats","runtime","artifact","browser","source",
       "quickNotes","memory","presentation"]
```

**全部默认 `true`**：

```js
Yz = Object.fromEntries(PN1.map(k => [k, true]))
```

### 3.2 容错归一 `U2t`

```js
function U2t(value) {
  if (typeof value !== 'object' || value === null || Array.isArray(value)) return Yz
  return Object.fromEntries(PN1.map(k => [k, typeof value[k] === 'boolean' ? value[k] : Yz[k]]))
}
```

三条容错：整体不是普通对象 → 全默认；数组 → 全默认；某个键不是布尔 → 该键默认。**这意味着一份旧版本存的 `taskMonitorSectionVisibility`（分组比现在少）升级后不会把新分组显示成 `undefined`。**

来源是 `xt().taskMonitorSectionVisibility`，使用处 `P = E ?? Yz`。

### 3.3 分组渲染的「强制显示」规则

在 `Tw0` 里：

```js
["runtime","artifact","browser","source"]
  .filter(k => sectionVisibility[k])
  .map(kind => ({ kind, items: highlights.filter(i => i.kind === kind) }))
  .filter(g =>
    g.items.length > 0 ||
    g.kind === "artifact" ||
    g.kind === "source" ||
    (g.kind === "runtime" && showSuggestion)
  )
```

**`artifact` 和 `source` 即使为空也保留；`browser` 空则消失；`runtime` 空但有自进化建议时保留。**

这是有意的不对称：产出和来源的空态在告诉用户「这一轮没有产出 / 没有引用」，是信息；网页查阅空着则没有意义。

`memory` 分组单独处理，`E1 = highlights.filter(i => i.kind === "memory")`，只有 `E1.length > 0 && sectionVisibility.memory` 才渲染——记忆分组连空态都不给。

空态文案（`emptyGroup.*`）：`暂无产出数据 :)` / `暂无网页查阅数据 :)` / `暂无技能与 MCP 数据 :)` / `暂无来源数据 :)` / `暂无记忆数据 :)`。**带一个笑脸**。

## 四、面板主体的结构

`x$` 接收一长串 props，内部按 `sectionVisibility` 逐项门控，顺序固定：

| 顺序 | 分组 | 门控条件 |
| --- | --- | --- |
| 1 | `w$` 关联 Issue | 有 issue 才渲染（不受可见性控制） |
| 2 | `i$` 视频 | `sectionVisibility.runtime` |
| 3 | `b$` 目标 | `sectionVisibility.goal` |
| 4 | `y$` 侧会话 | `sectionVisibility.sideChats` |
| 5 | 后台 Agent | `sectionVisibility.backgroundAgents` |
| 6 | 后台进程 | `sectionVisibility.backgroundProcesses` |
| 7 | `id1` 技能自进化 | `serviceAvailable && sectionVisibility.runtime` |
| 8 | `jD1` 快速笔记 | `showQuickNotesSection` = `experimentalQuickNotesEnabled && sectionVisibility.quickNotes` |
| 9 | `a$` 记忆 | `sectionVisibility.memory` |
| 10 | `Tw0` 完整列表 | 仅当 `model.highlights` 存在 |

**`Tw0` 里还有完整的一套**：`recap` / `goal` / `spec` / `backgroundAgents` / `backgroundProcesses` / `sideChats` / `runtime` / `artifact` / `browser` / `source` / `quickNotes` / `memory` / `presentation`。

也就是说**同一份数据有两条渲染路径**：分散的单组组件（上表 1–9）和聚合的 `Tw0`（上表 10）。这看起来是历史演进的结果——先有零散组件，后加了统一的 highlights 列表。

### 4.1 折叠行 `i6`

分组标题行组件，props：`title`、`open`、`onToggle`、`action`、`children`。`action` 是标题右侧的操作区（例如自进化分组的「N 条建议」徽标）。

`Tw0` 里用 `$l1 = 4` 做折叠阈值，展开按钮文案 `showMore:"查看更多（{{count}}）"` / `showLess:"收起"`。

> **与 09 的交叉引用**：轮次末尾的产出文件卡用的是另一个常量 `qv1 = 7`。两个阈值不是同一个东西，见 09 §四。

### 4.2 环境与分支小工具

- `pl1` / `Xz`：图标 + 标签 + 值的行。`displayMode === "fixed"` 时显示 label 文字，`floating` 时只留 tooltip + `sr-only`。
- `CC0`：执行环境切换，`workspaceKind` 是 `worktree` / `local`，菜单宽 `w-52`；不可切换时的禁用理由键是 `executionModeSwitchUnavailable`。
- `xv0`：分支与变更摘要，显示 `+additions` / `-deletions`，颜色 `text-success` / `text-error`。

## 五、与 09 的衔接：行模型是面板的地基

09 里拆过 `q41`（通用行）和 `sD1`（把一条自进化建议映射成行）。这里补上它在**面板侧**的意义：

```js
function sD1(suggestion) {
  return {
    id: `skill-evolution:${suggestion.id}`,
    kind: "runtime",
    origin: "automatic",
    label: suggestion.skillName,
    detail: "skill",
    target: { type: "message", messageId: suggestion.id },
    messageId: null, toolUseId: null, evidenceId: null, turnId: null
  }
}
```

一条技能自进化建议**不是专门的数据类型**，它被临时包装成一条 `kind:"runtime"` 的通用行，塞进「技能与 MCP」分组里渲染。`detail:"skill"` 让图标判定走 skill 分支。

**这个做法省掉了整个「建议条目」UI**：不需要为建议写一套行样式、图标、hover、缺失态、移除按钮，全部复用。

代价也清楚：`target.type = "message"` + `messageId: null` 意味着**这行点了不会导航**（没有真实 message 可跳），`sessionFileStatusEnabled: false` 关掉文件存活检查，`onRemove: () => {}` 是个空函数——只是因为 `q41` 的签名要求这些 prop。

## 七、能抄 / 不能抄

### 7.1 能抄（纯前端结构，搬过来就成立）

| 项 | 为什么能抄 |
| --- | --- |
| **「有坐标 = 钉住」的状态设计** | 一个状态代替两个布尔量，`unpin` 变成置 `null`，`resize` 重新夹取自然生效 |
| **拖拽排除交互元素** | `event.target.closest('button,input,a,textarea')` 一行守卫，是纯 DOM 逻辑 |
| **指针偏移而非位置增量** | 不累积误差，实现成本相同 |
| **夹取函数的两层兜底** | `Math.max(16, ·)` 防窗口比面板窄；最小可视高度 96 |
| **13 个分组全默认开的容错归一** | `U2t` 的三条容错（非对象 / 数组 / 非布尔键）能防止旧配置升级后新分组消失 |
| **空态不对称规则** | 「产出、来源即使空也显示」是信息设计，不依赖任何宿主能力 |
| **行模型复用** | 把专用条目临时包装成通用行，省掉一整套 UI |

### 7.2 不能抄（依赖宿主能力，本项目没有）

| 项 | 缺什么 |
| --- | --- |
| **三种容器形态** | 本项目面板在 `shell.overlay` 里（`inset:0; pointer-events:none`），没有「固定右栏」这个宿主槽位可用。详见 §八 |
| **`displayMode` 联动 padding / 标题色** | 同上——没有 fixed 形态，这套分支没有意义 |
| **`persistWorkbenchUiState` 统一落盘** | 宿主能力。本项目落盘路径是 `$DSH_HOME/plugin-data/skill-evolve/sessions/<sessionId>.json` |

## 九、复现方法

```python
import json, struct

path = r'F:\Qoder\resources\app.asar'
with open(path, 'rb') as f:
    head = f.read(16)
    hs = struct.unpack('<I', head[12:16])[0]
    header = json.loads(f.read(hs).decode('utf-8'))
    base = 16 + hs
    base = (base + 3) // 4 * 4          # 数据区按 4 字节对齐
    for name, info in header['files'].items():
        if not isinstance(info, dict) or 'offset' not in info:
            continue                     # 目录条目只含 files 键
        f.seek(base + int(info['offset']))
        data = f.read(int(info['size']))
        # data 即原始文件内容
```

**踩过的坑，记下来免得重犯**：

1. **对齐**：`base` 必须 `(base + 3) // 4 * 4`。忘了这一步，抽出来的 JS 前几个字符是乱的，后面全错位。
2. **不要用 `bash` 工具的 `grep` 搜中文**。它会把这个 `needle` 当成文件名，报 `grep: 产出: No such file or directory`。用 Python `str.find`。
3. **控制台是 GBK**。Python `print` 中文抛 `UnicodeEncodeError: 'gbk' codec can't encode`。一律写 UTF-8 文件再读。
4. **内置 `bash` 工具在本机反复崩溃**（`NtCreateDirectoryObject ... 0xC0000022`，退出码 3221225794）。改用 `ops_bash`。
