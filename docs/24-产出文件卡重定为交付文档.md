## 2. 其余对齐事实（写代码前要知道的）

- **五组** `runtime`/`artifact`/`browser`/`source`/`memory`，i18n
  `{artifact:"产出", browser:"网页查阅", runtime:"技能与 MCP", source:"来源", memory:"记忆"}`；
  空态 `{artifact:"暂无产出数据 :)", …}`。
- **空组策略不对称**：`artifact`/`source` 空也留组、`browser` 空即消失、`memory` 连空壳都不给。
- **折叠阈值 `$l1 = 5`**（`source` 永不折叠）；会话主体卡是 `qv1 = 7`。
- **去重键 `file:${path.replace(/\\/gu,"/")}`**（只归一斜杠，不折叠大小写）；
  主进程 `S_0` 另按 `pathKey`（Windows 小写）去重。
- **`entryKind` 支持目录**，但真实数据 **122/122 全为 `None`** —— 侧栏那段目录分支是死路径。
- **`origin` 真实数据 122/122 全是 `automatic`，零条 `manual`** —— 移除按钮从未出现过。
- **`artifact` 的 `detail` 就是完整绝对路径**（`detail === target.path`，31/31 相等），
  而 `label` 是 basename。
- **官方文档与代码不一致**：`docs.qoder.com/qoder/task-monitor` 写着
  `Output files are ordered by their actual last-modified time. Files that are no longer
  available appear after accessible files.`，但实测 5 个会话里 4 个按回合顺序而非 mtime，
  `Tw0` 里**零个 `sort`**，`Rx0` 只做去重合并不排序。**文档描述的 mtime 排序在 0.5.7 侧栏未实现。**

## 3. 为什么我们不照抄 Qoder 的通道 1

**因为我们的模型不写那种链接。** 实测 30 个会话 148 回合：

| 来源 | 文件数 | 过 23 项白名单后 |
| --- | --- | --- |
| A. 工具汇报（`present` / `report_output_files`） | **14** | 14 |
| B. 正文 markdown 文件链接（Qoder 通道 1 等价物） | **14** | 8 |
| C. A ∪ B | **27** | 21 |

- **A 与 B 完全不重叠**：A 是主动交付的文档；B 是正文顺手提到的路径，多数是
  `F:/…/client.js#L2982` 这类带行号的源码。
- 我们的模型**多用反引号包文件名**，不用 `[名字](路径)`，148 回合只有 14 处（7%）。

更关键的是，**宿主已经明确拒绝过这条通道**。`@deepseek-ai/dsh-client-ui-deliverables`
的源码注释原文：

> `produced paths come from successful first-party mutation calls and their recorded file
> targets, changed files from the Host's recorded git summary, and deliveries from present;
> never from presentation data or the closing prose.`

「never from … the closing prose」——宿主把「从收尾散文抽链接」写成了不做的事。
我们若照抄 Qoder 通道 1，就是在自己的插件里重新引入宿主刻意排除的启发式。

## 4. 为什么只留 `deliverables/presented`，而不是自己从 `present` 参数抠路径

宿主在每次 `present` 调用时**自己发一条结构化事件**，30 个会话里统计到 26 次：

```json
{"type":"deliverables/presented","seq":2591,"time":1794418340322,
 "data":{"turn":7,"callId":"call_00_1mFfkyp4x8FBAMW5T0U47152",
         "files":[{"path":"F:\\dsh-plugin\\dsh-skill-evolve\\docs\\16-上一轮总结卡定稿方案.md",
                   "description":"上一轮总结卡定稿方案：对照四份实现后的最终施工版"}]}}
```

三个理由：

1. **`files[].description` 是宿主给的现成描述**。Qoder 的行没有这个字段（它的 `detail`
   就是绝对路径）。这是我们能比 Qoder 多做一点的地方。
2. **结构化**：不受工具参数截断影响，不需要解析 JSON 字符串。
3. **两个副本都读、去重**：`present` 调用的参数里也有 `files`，但它可能被截断；
   事件里也有，两者是同一份副本。`deliver()` 按路径去重，所以重复到达不产生第二行。

```js

  'png', 'jpg', 'jpeg', 'gif', 'webp', 'svg',
  'mp4', 'webm',

const TEMPORARY_NAME = /^(?:~\$|\.~|~)/u
const UNDELIVERABLE_DIRS = new Set([
  '.cache', 'cache', 'tmp', 'temp', 'node_modules', '__pycache__',
  '.git', '.ssh', '.aws', '.qoder', '.qoder-cn', '.lingma',

function isDeliverable(path)   // 尾斜杠先拒、段级判目录、末段判扩展名、无扩展名拒
```

**为什么九张表变成一张**：旧九张表回答的是「哪些文件变了」，而新问题「哪些文档被交付了」
的答案里不可能出现锁文件、构建产物、临时脚本 —— 保留就是九张没人问的表。

**为什么 `UNDELIVERABLE_DIRS` 收窄了**（这一条是本轮的设计决策）：

原来的名单里写着 `_tmp-test`、`_qoder_rev`、`.review`、`.nyc_output` 与一串
`.rv-`/`.audit-`/`.tmp-`/`.probe-` 前缀 —— **产品代码里写着本仓库自己的临时目录名**。
那些名单是压四路采集噪声的；现在来源只剩声明（模型的明确动作），
**产品代码不该用作者的目录习惯覆盖它**。收窄后只留两组无需知道这是哪个项目就能辩护的：
依赖/构建 scratch（Qoder 自己的名单）与秘密/私有状态目录。
代价：end-to-end 测试的 fixture 建在 `_tmp-test` 下，改完之后立刻从 6 条红变 19/0 ——
**测试一直在告诉我这条规则错了，只是之前我把它当成测试环境问题。**

### 6.2 一条记录携带它被交付时的说法

`session-state.js` 的 `readPathEntry` 返回 `{ seq, turn, at, description }`；
`rememberPaths(sessionId, paths, turn)` 接受 `string | { path, description? }`，
`const kept = said.length === 0 && previous !== undefined ? previous.description : said`
—— **空描述不抹掉旧的**。

`transcript.js` 的 `deliver(path, description)` 则相反：**后到的非空描述覆盖旧的**
（`if (said.length > 0) existing.description = said`）。
两个方向不对称，理由是：写入层要防「同一份副本第二次到达时没带描述」，
显示层要认「模型第二次对这个文件说了新的话」。

### 6.3 六个图标桶

原来的八桶是「任何文件」时代的：`code`/`markup`/`style`/`data`/`doc`/`image`/`archive`/`file`。
收窄到交付文档后：

- `xlsx`/`xlsm`/`ppt`/`pptx`/`mp4`/`webm` **六种白名单后缀根本没有桶，全落空白页** ——
  而 office 三件套正是本场景的主角。
- `code`/`style`/`archive` 三类**永远不可能出现**（白名单里无源码后缀）。

重建为六桶，每个都是白名单子集：`doc`（`md markdown txt pdf doc docx`）、
`sheet`（`xls xlsx xlsm csv tsv`）、`slide`（`ppt pptx`）、`markup`（`html htm`）、
`image`（`png jpg jpeg gif webp svg`）、`video`（`mp4 webm`）。
`doc` 与 `file` 故意不上色，因为它们不主张性质。

**加了一条让两张表不可能再漂移的断言**：`every delivered suffix has a bucket` +
`and no bucket is claimed by a suffix the card would refuse`。

### 6.4 卡片长什么样

- 分组只按**回合**（`fresh` / `earlier`「更早」）与**存在性**（`gone`「已不存在」）。
  没有 `stale`「较早」、没有 `noise`「生成文件」。
- 主数字只数**交付文档**；被拒的另说一句 `另有 N 个文件不是交付文档`。
- 行 tooltip 三段：绝对路径 → 交付时的说法 → 「点击在侧栏预览」。
  **说法放 tooltip 不放第二行**：行高 28px，卡片可窄到 168px。
- `missing` 行褪色 + 删除线 + 不可点（对齐 Qoder 的三条）。
- **什么都没交付的会话不画卡**（`showFiles = delivered.length > 0`）：
  一张说「0 个文件 另有 12 个文件不是交付文档」的卡是在讲它没显示的东西。

### 更正 2026-11-21：真机截图发现的第七件事

上面第 1 条已完成。但截图同时拉出一件本文没写进来的事：
**卡片头部的灰字「另有 N 个文件不是交付文档」数的是 v1/v2 时代的采集记录。**

也可能来自只给路径的 `report_output_files`，分不开）。
代价是 237 个状态文件里 98 个的 `paths` 从此不再显示。
新增 DEF-179、D-241/242、R-109；全量 3854 断言全绿，四套突变 166 + 69 + 141 + 69 全杀。

这件事的教训写在 DEF-179 里：**一个字段名装了两个断言，而卡片只能说一个**。
宽容读是对的，但只在「新字段缺失」的情况下——不在「旧字段意思不同」的情况下。
