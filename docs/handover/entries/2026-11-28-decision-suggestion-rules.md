# D-20261128-rules · 建议的四个口径

细节与两轮评审的推导冻结在 `02-decisions.md` 的 `D-263`（分区预算）、`D-264`
（预测口径 + 允许弃权 + 40 字符）、`D-265`（叙述类丢弃）、`D-266`（同义去重范围）、
`D-269`（命中率人工评估）。这里是**仍然生效的结论**，给冷启动的人看。

## 决定

1. **口径是预测，不是建议。** 验收标准是「读者会说『我正想打这个』」，不是
   「这一步合理」。因此允许弃权（`{"suggestions":[]}`，`MIN_SUGGESTIONS = 1`），
   留白优于猜。
2. **提示词按区域分预算，规则区不计入数据预算。** 规则 ≤ 1000 字符固定成本；
   数据三区：`<latest_request>` ≤ 600、`<requests>` 合计 ≤ 600（单条 ≤ 200，
   超预算整条淘汰最旧的）、`<report>` ≤ 1200。合并成一个总预算时，规则会挤掉
   数据（实测数据只占 10%）。
3. **单条建议 ≤ 40 字符。** 实测（680px 行、文字区 642px）：纯中文第 44 字开始
   出省略号，纯英文 80 字符，中英混排 122。40 是「不会变成省略号」的实测值，
   不是审美值。
4. **只喂「上一轮汇报」+ 多轮请求背景。** 工具调用、文件编辑、命令一律不进
   提示词（用户裁决：对建议没有帮助）。
5. **命中率只做人工评估。** 自动指标会被刷成好看的数字；保留取样探针，让
   「模型有没有服从契约」可机械判断。

## 代价

- 40 字符会把一些本可以更具体的话截短；宁可短，也不要变成「...」。
- 弃权意味着有些回合一条建议都没有，读者可能误以为功能坏了；路由的 `reason`
  会写清是模型主动留白。

## 失效条件

若将来把芯片从单行改成两行（`white-space: normal`），40 这个数字的推导基础就没了，
必须重新实测再把上限改回去。
