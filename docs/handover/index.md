# 交接文档

这套文档是给**下一个接手的人（或下一个 agent）**看的，不是给用户看的产品说明。产品说明在 `README.md`，设计与论证在 `docs/01`–`docs/07`。

## 为什么单独建这一套

上下文会被压缩，会话会被换掉，多个 agent 可能并行改同一个仓库。压缩后的摘要是"别人对过去的转述"，转述会失真，而且失真的部分恰好是最容易被丢掉的**理由**。这套文件是**未经转述的原始记录**，它的价值在于：当某处代码看起来莫名其妙时，能在这里查到它当初为什么长这样。

## 铁律：只能追加，不能修改

**这套文件只许追加，不许改写已落盘的条目。**

- 每条记录带日期与变更理由。
- 发现旧记录写错了，**不要删改它**，在后面追加一条更正，写明「更正 YYYY-MM-DD：……」以及原来错在哪。
- 理由：这套东西的用途是「上下文失真时的唯一可信来源」。一旦允许改写，它就和摘要一样不可信了，而且你无法分辨哪部分被改过。

唯一的例外是每个文件的**索引表格**（文件开头那张表），新条目落盘时要在表里加一行。

## 分类

| 文件 | 记什么 | 什么时候写 |
|---|---|---|
| [`01-status.md`](01-status.md) | 当前做到哪一步、哪些是真的可用、哪些是半成品、已知缺口 | 每个大阶段结束时追加一节，不改旧的 |
| [`02-decisions.md`](02-decisions.md) | 架构决策记录（ADR）：每个非显然的选择、被否决的替代方案、否决理由 | 做出决策的当场 |
| [`03-defects.md`](03-defects.md) | 缺陷与教训：每个真实缺陷的现象、根因、修法、以及「为什么测试没抓到」 | 修完一个缺陷就追加一条 |
| [`04-reviews.md`](04-reviews.md) | 审查日志：每一轮代码审查的结论、我核实后的判定、哪些驳回及理由 | 每轮审查收敛后 |

## 怎么用

**接手时**，按这个顺序读：`01-status.md` 最后一节（现在在哪）→ `03-defects.md` 最后几条（最近在踩什么）→ `04-reviews.md` 最后一轮（审到哪了）。不要从头读，这些文件会越来越长。

**改代码时**，按 `README.md` 说的跑测试；改动涉及几何、面板、清单卡片时，三个变异套件必须都归零：

```bash
node test/run.mjs                      # 全量断言
node test/mutate-panel.mjs             # 面板连接的变异
node scripts/mutate-guards.mjs         # 几何守卫的变异
node scripts/mutate-checklist-panel.mjs # 清单卡片的变异
```

**审查规矩**（用户 m06781 定下的，已存为持久记忆）：每次修改代码后都必须代码审查；针对审查意见做的修复必须再审查，多轮直到收敛。审查结论记进 `04-reviews.md`。

## 与其它文档的边界

- `README.md`：给使用者看的——它能做什么、怎么装、怎么配、诚实的限制。
- `docs/01`–`docs/07`：调研、可行性、方案、以及外部审查意见。`05-设计方案.md` 有 25 章修订记录，是**最完整的技术论证**，但它有 1800 行，不适合作为第一次接触的入口。
- 本目录：给维护者看的骨架——状态、决策、缺陷、审查。

三者不重复：README 说「是什么」，05 说「为什么这样设计」，本目录说「现在在哪、踩过什么、下次别踩」。

## 更正 2026-11-01（七）：文档分层

拆包之后文档出现两个缺口，本轮补齐。

**缺口一：`packages/core` 与 `packages/mcp-evolve` 没有 README。** 两个包此前只在根 README 的表格里出现过一行。core 的读者最需要知道的恰好是表格装不下的：两个 `ageInDays` 语义相反且**不能合并**，以及「这个模块该放 core 还是放插件」的判据（将来 `mcp-evolve` 会不会也要用）。mcp-evolve 则需要说清为什么它是空的、填起来要解决什么。

**缺口二：`docs/` 下八份编号文档没有入口。** 新读者不知道哪份能信：`06` 已全部兑付、`08` 已执行、`05` 和 `07` 部分过期（路径仍是 `lib/index.js` 时代的）。新建 `docs/00-文档索引.md` 逐份标注状态。

**一条主动决定：不批量改写旧文档里的路径。** `02`、`05`、`06`、`07` 共提到 40 余处 `lib/*.js`。把它们替换成新位置看起来是在「维护文档」，实际是在伪造历史：`06` 是外部审查者对**当时那份代码**的意见，路径改了之后那些意见会读起来像是对着现在这份代码写的，而其中至少有两条当时就被驳回了。做法改为在 `00-文档索引.md` 里给一张旧路径 → 新位置的对照表，并明确写出「原文不改，发现失效就在本目录追加更正」。

**新的分层。** 与其它文档的边界因此多了两层：`packages/*/README.md` 是每个包自己的说明（它拥有什么、怎么配、故意不做什么），配置键只在各自的包里列；`docs/00-文档索引.md` 是编号文档的导航，按目的分类并标出每份的状态。

**规矩固化。** `docs/00-文档索引.md` 末尾写了四条维护规矩，其中两条是既有约定的复述：`handover/` 只增不改（用户 m20052 定），旧编号文档不改写。另两条是新的：包的 README 跟着包走、根 README 不重复列配置键（重复的那份会先过期）；新增编号文档时同步更新索引表的状态栏。
