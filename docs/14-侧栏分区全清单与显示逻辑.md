# 14 · Qoder 侧栏分区全清单与显示逻辑

> 逆向对象：Qoder 0.5.7，渲染层 `assets/gtdG4YpP.js`。
> 本文是 [11-侧栏与面板机制逆向.md](./11-侧栏与面板机制逆向.md) 的**下钻**：11 讲容器与分组开关，本文逐个分区拆**它到底显示什么、什么时候显示、什么时候消失**。
> 用途：供决策「哪些分区值得迁移到本项目」。本文只陈述 Qoder 的机制，迁移建议集中在 [§八](#八迁移评估改造现有卡优先)。

## 零、一句话结论

「任务监控」面板有 **15 个分区**，它们**不是同一种东西**，而是四类完全不同的显示逻辑混在一起：

| 类型 | 分区数 | 判据 |
| --- | --- | --- |
| **强制留位型** | 5（产出/技能与MCP/网页查阅/来源/记忆） | 有无数据 + 一条不对称的强制规则 |
| **有数据才显型** | 5（视频/子智能体/后台进程/侧边任务/记忆更新提示） | `items.length > 0` |
| **模式驱动型** | 4（目标/计划/环境/快速笔记） | 会话处于什么模式，不是有没有数据 |
| **永远渲染型** | 1（关联 Issue） | 无条件渲染，组件内部自己判断 |

**混在一起的结果是**：面板看起来像「一堆卡片」，实际上每张卡的生死规则都不一样，用户看到的顺序也是固定的 15 段。

## 二、四个 highlight 分区的显示规则（唯一有不对称设计的地方）

### 2.1 三层过滤

```js
// 第一层：按可见性开关过滤，并分组
b1 = ["runtime","artifact","browser","source"]
  .filter(k => V[k])
  .map(kind => ({ kind, items: v1.filter(i => i.kind === kind) }))

// 第二层：强制留位规则
.filter(g =>
  g.items.length > 0 ||
  g.kind === "artifact" ||
  g.kind === "source" ||
  (g.kind === "runtime" && showSkillEvolutionSuggestion)
)
```

| kind | 空时 | 理由 |
| --- | --- | --- |
| `runtime` | 消失（除非有自进化建议） | 没有技能调用就没有信息 |
| `artifact` | **保留**，显示「暂无产出数据 :)」 | 空态本身是信息：这一轮确实没产出文件 |
| `browser` | 消失 | 没查网页不需要占位 |
| `source` | **保留**，显示「暂无来源数据 :)」 | 同 artifact |
| `memory` | 单独处理，`length > 0 && V.memory` 才渲染，**连空态都不给** | 记忆是全局的，会话级空态没意义 |

**这是整个面板里最值得学的一条设计**：`artifact` 和 `source` 的空态有信息价值，所以强制留位；其余没有，所以消失。它不是「统一规则」，是**逐个判断哪些空态有意义**。

### 2.2 空态文案

```js
emptyGroup: {
  artifact: "暂无产出数据 :)",
  browser:  "暂无网页查阅数据 :)",
  runtime:  "暂无技能与 MCP 数据 :)",
  source:   "暂无来源数据 :)",
  memory:   "暂无记忆数据 :)"
}
```

**都带一个 `:)`。** 这是刻意的语气选择——空态里自嘲一下，比「暂无数据」温和。

### 2.3 折叠规则（按类型区分）

```js
U1 = (kind === "runtime" || kind === "artifact" || kind === "browser" || kind === "memory")
  ? Math.max(0, items.length - $l1)
  : 0
```

`$l1 = 4`（模块顶部常量，偏移约 10131）。

| kind | 折叠 | 显示条数 |
| --- | --- | --- |
| `runtime` | 是 | 4 + 「查看更多（N）」 |
| `artifact` | 是 | 4 + 「查看更多（N）」 |
| `browser` | 是 | 4 + 「查看更多（N）」 |
| `memory` | 是 | 4 + 「查看更多（N）」 |
| **`source`** | **否** | **全部显示** |

**`source` 不折叠**是有道理的：来源通常就两三条（引用的网页、文档），而产出可能是几十个文件。

### 2.4 `runtime` 分区的特殊拼装

```js
xe = kind === "runtime" && showSkillEvolutionSuggestion
  ? [...suggestions.map(sD1), ...items.filter(x => !suggestions.some(s => SD(x) && x.label === s.skillName))]
  : items
```

**自进化建议排在技能调用前面**，且**同名技能去重**——已经作为建议出现的技能，不再重复显示它的调用记录。

### 2.5 `source` 分区的额外能力

只有来源分区有「添加来源」按钮（`action`）：

```js
kind === "source" && localActions
  ? <DropdownMenu>
      <MenuItem onSelect={onAddFile}>添加文件</MenuItem>
      <MenuItem onSelect={openLinkDialog}>添加链接</MenuItem>
    </DropdownMenu>
  : null
```

且 `contextMenuDisabled: kind === "source"` —— **来源分区的标题行禁用了右键菜单**，因为它自己有添加按钮，不需要径向菜单。

添加链接走一个模态框（`linkDialog`）：校验 `http://` 或 `https://` 前缀，文案「将一个 HTTP 或 HTTPS 链接加入输入框，发送后会记录为来源。」——**注意是「加入输入框」而不是「直接加来源」**，这个来源要经过一次消息发送才真正产生。

### 2.6 去重：只对两类做

```js
function Rx0(items, sideChatArtifacts) {
  const merged = [...items]
  const keys = new Set(
    items.filter(x => x.kind === "artifact" || x.kind === "memory").map(x => Ul1(x))
  )
  for (const x of sideChatArtifacts) {
    if (x.kind !== "artifact" && x.kind !== "memory") continue
    const key = Ul1(x)
    if (keys.has(key)) continue
    keys.add(key)
    merged.push(x)
  }
  return merged
}
```

**侧边任务的产出只合并 `artifact` 和 `memory` 两类**（技能与 MCP、网页查阅不合并）。去重键：

```js
function Ul1(e) {
  const t = e.target
  return t.type === "file"    ? `file:${t.path.replace(/\\/gu, "/")}`
       : t.type === "url"     ? `url:${t.url}`
       : t.type === "message" ? `message:${t.messageId}`
       :                        `evidence:${t.evidenceId}`
}
```

**反斜杠统一成正斜杠**再比较，所以 Windows 路径和 POSIX 路径能正确去重。

## 三、五个「有数据才显」分区

这些分区的规则最简单，但每个的「数据」来自很不同的源。

### 3.1 视频生成 `i$`

```js
function i$({ sessionId, displayMode }) {
  const summary = p1(store.sessionIdObs)
  const videos = p1(store.videosObs)
  if (summary !== sessionId || !videos.length) return null
  return <Section title="视频生成">
    {videos.slice(-40).map(v => <GenericRow item={{
      id: v.videoId, kind: "runtime", origin: "automatic",
      label: v.name || "视频",
      detail: t(`chatSession.videos.${...}`),
      target: { type: "message", messageId: v.messageId },
      ...
    }} />)}
  </Section>
}
```

**两个细节**：

1. **`videos.slice(-40)`**：只显示最近 40 个。面板是「当前状态」视图，不是历史归档。
2. **`detail` 的取值有个特殊分支**：

```js
v.result.status === "completed" && !v.result.filePath ? "undelivered" : v.result.status
```

**「生成了但没下载到工作区」被单独标成 `undelivered`**（未下载到工作区），而不是笼统的「已完成」。这是产品级的细心——用户会困惑「说完成了但文件在哪」。

状态枚举：`generating` 等待结果 / `completed` 已交付 / `failed` 生成失败 / `stopped` 已停止 / `undelivered` 未下载到工作区。

### 3.2 子智能体 `S$`

```js
function S$({ runs, onOpen }) {
  if (runs.length === 0) return null
  const sorted = [...runs].sort(VD1)
  ...
}

function VD1(a, b) {
  const ia = sd1(a.status), ib = sd1(b.status)
  return ia !== ib ? (ia ? 1 : -1)
       : a.startedAt.localeCompare(b.startedAt) || a.taskId.localeCompare(b.taskId)
}
function sd1(status) {
  return status === "completed" || status === "failed" || status === "stopped"
}
```

**排序规则**：未结束的排前面，同组内按 `startedAt` 升序，再按 `taskId` 兜底（保证稳定排序）。

行内显示：**头像**（`sA`，用 `toolUseId ?? taskId` 作 seed）+ 名称 + 状态。

名称回退链：

```js
label = subagentTitle ? t("chatActivity.subagentTitle", {name, task}) 
      : name || task || description
```

状态只在**已结束**时显示文字（`角色 = "img"` + `aria-label`），运行中只显示图标。这是「运行中不必说，结束了才需要告诉结果」。

角色名映射 `_x0`：`frontend-dev` → 前端开发、`backend-dev` → 后端开发、`qa` → 测试、`code-reviewer` → 代码审查、`researcher` → 调研、`ux-designer` → 交互设计、`operations` → 运维、`debugger` → 调试。

### 3.3 后台进程 `L$` + 虚拟列表

**这是唯一用虚拟滚动的分区**：

```js
function fC0({ runs, scrollElement, renderRun }) {
  return runs.length <= 50
    ? <div className="flex flex-col gap-0.5">{runs.map(renderRun)}</div>
    : <gC0 ... />   // 虚拟滚动
}
```

**50 条是分界点**：`<= 50` 直接渲染，`> 50` 切虚拟滚动（`estimateSize: () => 28`、`gap: 2`、`overscan: 4`、`initialRect: {width: 280, height: 524}`）。

虚拟列表的 `rangeExtractor` 有一处细心：

```js
const set = new Set(gN(range))
if (focusedIndex >= 0) {
  for (let i = Math.max(0, focusedIndex - 1); i <= Math.min(range.count - 1, focusedIndex + 1); i++) set.add(i)
}
```

**聚焦项的前后各保留一条**，避免键盘 Tab 到相邻项时因为还没渲染而跳掉焦点。

行的主体是按钮，`title` 的取值：

```js
run.kind === "monitor" && run.command ? `${run.description} ${run.command}` : run.command ?? run.description
```

**监控型任务同时显示描述和命令**，普通进程只显示命令。

### 3.4 侧边任务 `y$`

```js
const visible = items.filter(p => p.lifecycleState !== "closed")
if (visible.length === 0) return null
const sorted = [...visible].sort((p, v) =>
  nd1(p) - nd1(v) || v.lastActivityAtEpochMs - p.lastActivityAtEpochMs
)
const expiredCount = visible.filter(p => p.lifecycleState === "expired").length
```

**过滤掉 `closed`，按状态优先级排序，同状态内按最后活动时间倒序。**

标题行右侧在 `expiredCount > 0` 时出现「清理全部已过期侧边任务」。

状态枚举（`sideChat.status`）：`running` 执行中 / `waitingUser` 等待处理 / `ready` 可继续 / `cold` 可继续 / `expired` 已过期 / `unavailable` 不可用 / `cleaning` 清理中 / `cleanupFailed` 清理失败。

**注意 `ready` 和 `cold` 的中文都是「可继续」**——内部状态不同（热/冷），对用户是同一件事。

还有一个「临时 vs 持久」的区分：

| 键 | 文案 |
| --- | --- |
| `temporary` | 临时侧边任务 |
| `temporaryDescription` | 这是临时任务，关闭标签或 Qoder 后将被清理；未发送的草稿也不会保留。 |
| `persistentDescription` | 关闭标签或 Qoder 后仍会保留，可从任务监控继续或清理。 |

### 3.5 记忆更新提示 `Nw0`

**这不是「列出记忆」，是一个一行提示条**：

```jsx
<section className="flex h-[18px] items-center gap-2 pl-1.5">
  <h3 className="flex min-w-0 flex-1">
    <button onClick={openMemorySettings}>
      记忆已更新
      {lastSeenSignature !== signature && <span className="size-1.5 rounded-full bg-info" />}
    </button>
  </h3>
  <button aria-label="打开记忆设置"><SettingsIcon /></button>
</section>
```

三个细节：

1. **两个入口都指向设置页**（`push({kind:"settings", section:"memory", query:""})`），不展示记忆内容。
2. **蓝点只在「有更新」时显示**，判据是 `lastSeenSignature !== signature`，`updateSignature` 由外部传入。
3. **行高固定 18px**，与 `_N1` 的标题行一致——它和「快速笔记」用的是同一个容器组件 `_N1`。

## 四、四个「模式驱动」分区

这些分区的显示条件不是「有没有数据」，而是「会话处于什么状态」。

### 4.1 目标 `b$`

```js
function b$({ goal, showTitle = true }) {
  if (!goal) return null
  const text = stripCodeBlocks(goal.objective).replace(/\s+/g, " ")
  ...
}
```

- **目标正文先剥掉代码块**（`LD` 把 ` ```...``` ` 整段删掉），再压成单行。
- 单行 + `truncate` + `title` 完整文本 —— 面板里**只显示一行目标**，要看全文得去别处。
- 门控：`goal` 存在 **且** `V.goal`。

目标状态相关文案有五种：`active` 目标 / `completed` 已完成的目标 / `paused` 已暂停的目标 / `blocked` 已阻塞的目标 / `usageLimited` 用量受限的目标 / `budgetLimited` 预算受限的目标。

**「用量受限」和「预算受限」是两种不同的中止原因**，分开命名说明这两种情况会真实发生。

### 4.2 计划 `Zw0`

```js
function Zw0({ artifact, displayMode, onOpen }) {
  if (!artifact) return null
  const title = planTitle(artifact) || t("chatSession.specArtifact.title")
  const textColor = displayMode === "fixed"
    ? "text-text hover:text-text"
    : "text-text-secondary hover:text-text"
  ...
}
```

**`displayMode` 影响标题颜色**：固定右栏用 `text-text`（主色），浮层用 `text-text-secondary`（次要色）。理由很实际——浮层里内容本来就少，用主色会显得吵。

计划的状态：`pending` 待确认 / `approved` 已批准 / `accepted` 已接受。另有 `feedback` 反馈、`edited` 已编辑 / `notEdited` 未编辑。

**空态是有的，但只在专门页面**：`emptyTitle:"还没有计划产物"` + `emptyDescription:"完成规划后，生成的计划会显示在这里。"`。面板里的这个分区在 `specArtifact` 为空时直接不渲染。

### 4.3 环境信息：单仓与多仓两条完全不同的路径

**单仓（`repositories.length === 1`）**：

```js
<i6 title="环境信息" open={L1("environment")} onToggle={...}>
  <Hl1 ... developmentServers={devServers} showTitle={false} />
</i6>
```

**多仓（`> 1`）**：

```jsx
<section aria-label="环境信息" className="flex min-w-0 flex-col gap-4">
  {repositories.map((repo, index) => (
    <div data-task-monitor-repository={repo.rootId}>
      <i6 title={repo.label} open={ee(repo.rootId, index)} showIndicator>
        <Hl1 ... developmentServers={null} grouped />
      </i6>
    </div>
  ))}
</section>
```

三个差异：

1. **多仓时分组标题是仓库名**，不是「环境信息」。
2. **多仓时默认只展开第一个**（`ee(rootId, index)` → `index === 0`），单仓默认展开。
3. **多仓时 `developmentServers` 传 `null`** —— 开发服务只在单仓模式下显示。这是合理的简化：多仓里开发服务归属不明。

`showIndicator` 让折叠标题多一个状态圆点。

**`environment` 不在 `PN1` 的 13 个分组里**，所以它没有可见性开关，只受 `showEnvironment` 控制。但它的折叠状态用了 `L1("environment")` —— **用了一个不在可见性表里的键做折叠记忆**，读代码时容易误以为它是可开关的分组。

环境信息包含：变更（`+additions/-deletions`）、执行位置（本地 / Worktree / SSH 主机 / 对等设备）、分支（可检出）、开发服务列表、提交或推送、拉取请求状态。

### 4.4 快速笔记 `jD1`

```js
function jD1() {
  return <_N1 title={<TaskMonitorTitle />} action={<TaskMonitorAction />} data-task-monitor-quick-notes-section />
}
```

**组件本身只是个标题行，没有列表。** 内容在另一个界面（`_N1` 是标题条容器，打开后跳转）。

文案：`title:"Quick Notes"`（**中文也是英文**）、`description:"保存从 Agent 回复中摘出的片段。"`、`open:"打开速记板"`、`close:"关闭速记板"`。

有完整的搜索、图片批注（矩形/椭圆/直线/画笔/文字/马赛克）、多图预览（缩放、翻页、复制、保存）。**这是一个独立的小产品，只是入口挂在任务监控里。**

门控是 `showQuickNotesSection = experimentalQuickNotesEnabled && V.quickNotes` —— **双重开关**：既是实验特性，又要分组可见性打开。

## 五、两个特殊分区

### 5.1 关联 Issue `w$`：唯一无条件渲染的

```js
function w$({ sessionId }) {
  const summary = p1(store.summaryObs)
  const { turns } = useTurns({ chatSessionId: sessionId })
  const { issues } = useIssues()
  const latestTurnIssue = turns.reduce((best, turn) =>
    turn.issueId && (!best || turn.startedAt > best.startedAt) ? turn : best, undefined)
  const issueId = (summary?.sessionId === sessionId ? summary.collaborationIssueId : undefined)
                ?? latestTurnIssue?.issueId
  const issue = issues.find(x => x.id === issueId || (!issueId && x.sessionId === sessionId))
  return issue ? <i6 title="关联 Issue">...</i6> : null
}
```

**它不在 `b1` 里，不参与 `sectionVisibility`，但 `Tw0` 无条件调用它。** 组件内部自己决定返回 `null`。

Issue 的解析有三级回退：

1. `summary.collaborationIssueId`（但要求 `summary.sessionId === 当前会话`，防止串会话）
2. 最近一个带 `issueId` 的 turn
3. 兜底：`issues.find(x => x.sessionId === sessionId)` —— 会话直接关联的 issue

**三级回退说明这个字段在不同历史版本里存的位置不一样**，代码兼容了所有情况。

行的内容：状态图标 + `identifier`（等宽字体）+ 标题（truncate）。

### 5.2 插件会话资源 `a$`

```js
function a$({ sessionId }) {
  const { sessionResources } = t1(pluginService)
  const state = p1(sessionResources.state)
  useEffect(() => { sessionResources.initialize() }, [sessionResources])
  return <>
    {state.failed && <div role="alert">
      <p>插件会话资源不可用</p>
      <button onClick={() => sessionResources.refresh()}>重试</button>
    </div>}
    {state.sections.filter(x => x.visible).map(section => <uC0 section={section} sessionId={sessionId} />)}
  </>
}
```

**这是插件扩展点**：其他插件可以往任务监控里塞自己的分区，通过 `{pluginId, contributionId, sessionId}` 注册，宿主提供 `summaryObs` 与 `runtimeStateObs`。

失败时**不整块消失，而是显示错误 + 重试按钮**（`role="alert"`）。

## 六、折叠组件 `i6` 与其他容器的分工

面板里其实有三种标题条容器，容易混淆：

| 组件 | 形态 | 用途 |
| --- | --- | --- |
| `i6` | **可折叠**，`data-task-monitor-collapsible-section` | 目标/计划/环境/子智能体/后台进程/四个 highlight 分组/关联 Issue |
| `_N1` | **纯标题行**（18px 高），无折叠 | 快速笔记、记忆更新 |
| `y$` 内部 | 自绘标题行 | 侧边任务 |
| `Fw0` | 独立卡片 | 任务回顾（不折叠，自带 216px 高度上限） |

`i6` 的细节：

- `expandLabel` / `collapseLabel` 都等于 `title`（无障碍朗读用）。
- `headerAction` 是标题右侧操作区（如「N 条建议」「添加来源」）。
- `showIndicator` 让标题末尾多一个状态点。
- `contextMenuDisabled` 为真时**吞掉右键菜单**（来源分区用）。
- 内部用 `BN` 组件，`isLast: true`、`padding: "none"`。

`_N1` 的定义极简：

```js
function _N1({ title, action, ...rest }) {
  return <section className="flex h-[18px] min-w-0 items-center gap-2 pl-1.5" {...rest}>
    <h3 className="flex min-w-0 flex-1">{title}</h3>
    <div className="flex shrink-0 items-center">{action}</div>
  </section>
}
```

**固定 18px 高、左内边距 1.5（6px）、gap 2（8px）** —— 这三个数在面板里反复出现，是这套排版的基准单位。

## 七、几个跨分区的共同约定

| 约定 | 值 | 出现在 |
| --- | --- | --- |
| 标题行高 | `h-[18px]` / `h-7`（28px，可折叠的触发器） | `_N1` / `i6` |
| 列表项行高 | `min-h-7` | `q41` |
| 分组间距 | `gap-2`（8px） | `Tw0` 外层 |
| 列表内间距 | `gap-1.5`（6px） | 各分组内容 |
| 字号 | 标题 `text-xs`（12px）/ 正文 `[12px]` / 次要 `[11px]` | 全部 |
| 主色 | `text-text` | 固定右栏、可点击标题 |
| 次要色 | `text-text-secondary` | 列表项文本 |
| 三级色 | `text-text-tertiary` | 不可折叠的标题 |
| 四级色 | `text-text-quaternary` | 空态、状态文字 |
| hover 背景 | `bg-fill-tertiary` | 所有可点行 |
| 内边距 | `px-1.5`（6px）/ `px-3`（12px） | 行 / 面板 |

**`px-1.5` + `h-[18px]` + `text-xs` 这三件套是面板排版的最小单位**，几乎所有标题行和空态都用这一组。

## 八、迁移评估（改造现有卡优先）

### 8.1 一一对照表

| Qoder 分区 | 本项目对应 | 差距 |
| --- | --- | --- |
| **产出** `artifact` | 产出文件卡（`client.js:2424`） | 有卡，但只记路径、无存活状态、无类型、无折叠分组 |
| **技能与 MCP** `runtime` | 技能与 MCP 卡（`client.js:2403`） | 有卡；Qoder 还混了自进化建议与视频 |
| **任务回顾** `recap` | 上一轮卡（`client.js:2366`） | 有卡；Qoder 是 216px 独立卡片 + 移交功能 |
| **来源** `source` | 无 | 本项目没有「引用来源」概念 |
| **网页查阅** `browser` | 无 | 本项目不追踪网页访问 |
| **记忆** `memory` | 无（记忆是宿主能力） | 本项目面板不碰记忆 |
| **视频生成** | 无 | 无此能力 |
| **目标** / **计划** | 无 | 无目标模式、无计划模式 |
| **环境信息** | 无 | 无 git 面板、无开发服务 |
| **子智能体** / **后台进程** | 无 | 无后台任务体系 |
| **侧边任务** | 无 | 无侧会话 |
| **关联 Issue** | 无 | 无 Issue 集成 |
| **插件会话资源** | 无 | 本项目的面板本身就是插件，不需要再嵌一层 |
| **快速笔记** | 无 | 无此功能 |
| **候选审核卡** | **Qoder 无对应** | **本项目独有，比 Qoder 强** |
| **面板设置卡** | Qoder 在全局设置里 | 本项目内嵌在面板里 |

**结论：15 个分区里，本项目有对应物的只有 3 个**（产出、技能与 MCP、上一轮/回顾），另有一个是 Qoder 没有的（候选审核）。其余 11 个都依赖本项目不存在的能力（git、后台任务、侧会话、Issue、视频、目标模式、计划模式、记忆、快速笔记、插件扩展点）。

### 8.2 能改造现有卡的三组（推荐先做）

按「不新增数据源、只改展示与状态」筛选：

**第一组：产出卡 ← 对齐 `artifact` 分区**

| 项 | 现状 | 改后 | 成本 |
| --- | --- | --- | --- |
| 缺失文件保留 + 删除线 | `api.js:443-446` catch 后不 push，静默丢弃 | 保留条目，标 `missing`，删除线 + tooltip「文件已被删除或移动」 | 半天 |
| 折叠阈值与文案 | `FOLDED_FILES = 4`，头部与按钮数字不一致 | 对齐 `$l1 = 4` 的「查看更多（N）」 | 十分钟 |
| `runtime` 在 `artifact` 之前 | 本项目「技能与 MCP」也在「产出文件」之前 | 已经一致，无需改 | — |

**这三项全部来自 docs/10 的 P0/P2，已经评估过，不需要新的逆向结论支撑。**

**第二组：技能与 MCP 卡 ← 对齐 `runtime` 分区**

| 项 | Qoder 做法 | 本项目可行性 |
| --- | --- | --- |
| 自进化建议混入本组，排在技能前面 | `[...suggestions, ...skillCalls]`，同名去重 | **可做**——但本项目的候选不支持按会话归属（无 `sourceSessionId`），只能全局显示 |
| `detail` 次要文字 | `kind === "browser" \|\| kind === "runtime"` 时在 label 后追加 | 可做，成本极低 |
| 空态 | 「暂无技能与 MCP 数据 :)」 | **可做**，但要注意本项目的卡现在是「有数据才渲染」，加空态会改变面板长度 |

**第三组：上一轮卡 ← 对齐 `recap` 分区**

| 项 | Qoder 做法 | 本项目可行性 |
| --- | --- | --- |
| 独立卡片 + 216px 高度上限 | `max-h-[216px]` + 展开态去掉上限 | 可做 |
| 顶部渐变背景 | `bg-gradient-to-b from-fill-quaternary from-[24.342%] to-bg-layout` | 可做，纯 CSS |
| 悬停才显形的「更多操作」 | `opacity-0 group-hover/recap:opacity-100` | 可做 |
| 移交到新任务 | 生成脱敏交接文档 → 在新会话继续 | **不可做**——本项目无「开新会话」能力 |

### 8.3 不建议迁移的（附理由）

| 项 | 理由 |
| --- | --- |
| **11 个依赖不存在能力的分区** | 视频/目标/计划/环境/子智能体/后台进程/侧边任务/Issue/记忆/快速笔记/插件扩展点，每一项都需要先建整套业务 |
| **`source` 的「添加来源」** | 需要一个「引用来源」的数据模型，本项目连产出都是只记路径 |
| **虚拟滚动（>50 才启用）** | 本项目 `MAX_PATHS = 200`，但折叠阈值只有 4，展开态最多 200 行。200 行不需要虚拟滚动 |
| **空态笑脸 `:)`** | 语境不同。Qoder 的空态是「这一轮没产出」，本项目的卡是「没数据就不出现」，加空态反而占地方 |

### 8.4 只有一条机制值得单独抽出来（附本项目核实结果）

**`Rx0` / `Ul1` 的去重键规范化**：

```js
`file:${path.replace(/\\/gu, "/")}`
```

**反斜杠统一成正斜杠再比较。**

本项目对应处的情况（已核实，结论与初判不同）：

- `session-state.js:607` 的 `paths` Map **用原始路径字符串作键**，不做归一化。所以 `F:\a\b` 和 `F:/a/b` 会存成两条记录。
- **但不会造成用户可见的重复行**：`api.js:423` 的 `statTouchedFiles` 在 `stat` 之前把每条路径解析成绝对路径，再用 `seen` Set 按绝对路径去重（`api.js:428-430`），保留先出现的那条。而 `pathsSeen` 返回的正是「最近在前」的顺序，所以保留的就是最新的那条，顺序也正确。

**所以这不是 bug，是一处浪费**：同一文件的两条记录会各占一个 `MAX_PATHS = 200` 的槽位。只有在「同一文件被两种写法反复写入、且会话路径数接近 200」时才会挤掉别的文件。

要不要在 `rememberPaths` 里加一行 `path.replace(/\\/g, '/')` 归一化，属于可选优化，不是必须修的东西。**我在这次核对里起初把它当成了 bug，实际读 `statTouchedFiles` 后否掉了——记在这里避免后面重复踩。**
