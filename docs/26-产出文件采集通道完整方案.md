## 2 Qoder 的完整三层（这次读全的部分）

### 2.1 通道 1：`w_0` —— 工具产物 + 末条正文链接

```
b_0(turnId, messages) =
    [ 最后一条 completed assistant 的完整 L11 ]      ← 含正文 markdown 链接
  + [ 每条 assistant 的 L11(text="", parts=[]) ]     ← 只有工具产物
  去重 → 白名单
```

正文链接由 `f_0` 抽：markdown lexer（`gfm:true, breaks:false`）的 `walkTokens`，只收 `type==="link"||type==="image"` 且 `raw` 匹配 `/^!?\[/` 的 `href`。
正文文本由 `x_0` 取：`parts` 里 `type==="text" && !parentToolUseId && text` 拼起来，无 `parts` 时退回 `e.text`。

**这一条 DSH 宿主明确拒绝**（`ui-deliverables/lib/client.js:1065` 注释原文）：
> `produced paths come from successful first-party mutation calls and their recorded file targets, changed files from the Host's recorded git summary, and deliveries from present; never from presentation data or the closing prose.`

所以**通道 1 我们不抄**，这是有意的，不是遗漏。

### 2.2 通道 2：`Q_0`/`U_0` —— 五个来源

| # | 来源 | 细节 |
| --- | --- | --- |
| 1 | shell 命令（`bash`/`exec`/`exec_command`/`run_command`/`shell`，去 `tool-` 与 `mcp__xxx__` 前缀） | `I_0(command, cwd)`：按 `;`/`&&` 切段（跳过引号与转义）；**任一段含 `\|\|` 或裸 `&` 就整条放弃**；逐段跟进 `cd`；`git mv`/`cp`/`mv` 记 copy/move、`rm`/`del` 记 remove；重定向目标（跳过 `&1`）；`tee`/`touch`；`curl\|pandoc\|wget` 的 `-o`/`-O`/`--output`；chrome 系 `--headless` 的 `--print-to-pdf=`；`node`/`python\d*` 用正则抽代码里的写入（`open(...,"w"/"a"/"x"/"+")`、`Path(...).write_text/write_bytes`、`save`/`to_csv`/`to_excel`/`writeFile`），python 还取 heredoc 或 `-c` 正文 |
| 2 | `imagegen` | 从 `response` 正则抽 `Image generated successfully. Saved to: <path>` / `absolute path of the image is: <path>` |
| 3 | `write`/`writefile`/`write_file` | **`writeFileBefore?.exists === true` 就返回 `[]` —— 只算新建**；否则先从 `response` 抽 `File created successfully at: <path>`，退回 `writeFileBefore.exists === false && writeFileBefore.error === null` 时用 `input` 路径 |
| 4 | `apply_patch` | 只认 `/^\*\*\* Add File: (.+)$/gmu`（**不认 Update/Delete**）；patch 长度 > 65536 跳过 |
| 5 | `fileChangeSet.files` | 只认 `operation === "add"`；`remove` 会把已加的 pathKey `delete` 并记入「不要再加」集合 |

另有 `create`/`createfile`/`create_file`/`filecreate`/`file_create` 与 `generatedVideo`（`status === "completed"` 且有 `filePath`）。
通用路径键优先级：`["file_path","filePath","path","target_path","targetPath","target"]`。
`_m1` 拒绝：空、`-` 开头、含 `/[\0\r\n$`*?{}[\]<>|&;]/u`。路径长度 > 4096 跳过。

## 4 关键发现：宿主已经替我们写好了「通道 2」

`F:\DSH\resources\app.asar` 里的 `@deepseek-ai/dsh-client-ui-deliverables`（`lib/client.js`，111,074 字节），`mutationPath` 原文：

```js
function mutationPath(name, argsRaw) {
  let args;
  try { args = JSON.parse(argsRaw); } catch { return null; }
  if (!isRecord(args)) return null;
  switch (name) {
    case "write": return typeof args.content === "string" ? pathValue(args.file_path) : null;
    case "edit": return validEditArgs(args) ? pathValue(args.file_path) : null;
    case "str_replace_editor": return editorMutationPath(args);
    default: return null;
  }
}
```

`validEditArgs`：`old_string` 非空字符串、`new_string` 是字符串且 `!== old_string`、`replace_all` 缺省或布尔。
`editorMutationPath`：`command` 为 `create`（要 `file_text` 字符串）/`str_replace`（要 `old_str` 非空）/`insert`（要整数 `insert_line >= 0` 与 `new_str`）。

配套的 `producedForClosing(data, seq)` 做三件事：
1. 只认 **`tool/result` 且 `isError !== true`** 的调用（失败的不算）；
2. 路径优先用 **`tool/result` 的 `meta.path`**（宿主的「记录的绝对目标」），`meta.path` 不是绝对路径时才退回 `arguments` 里的路径，两者都不是绝对路径就丢弃；
3. `seq > 收尾 assistant 的 seq` 的排除，`seen` 去重保首次出现顺序。

**宿主还有一条我们没有的**：`workspace/changes` 事件 —— 真实会话里实测存在（`session-de0dfca5` 4 条、`session-798cf` 1 条），形状 `{"type":"workspace/changes","seq":1226,"data":{"turn":4}}`，配合 `/api/changes.summary` 与 `/api/changes.diff` 两个路由取内容。**我们连这个事件都没订阅。**

## 5 完整方案

分三档：**必须补** / **可选** / **明确不补**。每条附证据与代价。

### 5.1 必须补：P1 —— 接宿主已有的 `produced` 通道（不含 shell）

**做法**：在 `transcript.js` 里新增 `MUTATION_TOOLS` 分支，规则照抄宿主（不是照抄 Qoder），并且**只在「本回合一次声明都没有」时启用**。

```js
// 伪代码
const MUTATION_TOOLS = new Set(['write', 'edit', 'str_replace_editor']);

// tool/call 时记下 callId → { path, isNew }
// tool/result 时若 isError !== true 且 path 是绝对路径，加入 this.produced
```

关键取舍（逐条给理由）：

| 取舍 | 选择 | 理由 |
| --- | --- | --- |
| `edit` 算不算 | **算** | 宿主算；Qoder 不算。区别在于场景：宿主是「改了什么」，Qoder 是「交付了什么」。我们的场景是交付文档，但**对 `.md` 这种文件，`edit` 是主要写法**（我们自己的 24 号文档就是先 `write` 后 `edit` 补的） |
| 要不要 `writeFileBefore.exists` | **不接**（我们没有这个字段） | 宿主靠 `tool/result.meta.path` 判绝对路径，不需要 `writeFileBefore`。Qoder 用它只为区分「新建 vs 覆盖」，而我们只关心「是不是交付文档」 |
| 失败的结果 | **排除** | 宿主 `isError === true` 直接 return，Qoder 只在 completed 消息里取 |
| 与声明的关系 | **声明优先，`produced` 只在零声明时兜底** | 这是 Qoder `q_0` 的 `n.length ? n : Q_0(...)` 结构。两者混用会让「模型特意挑的 2 个」被「它碰过的 20 个」淹没 |
| 白名单 | **仍然过 23 项** | 否则 `.py`/`.js`/`.json` 会灌满卡片（`session-151cb1ab` 那 6 个 `patch_*.py` 就是反例） |

**预估收益**：实测 `only_write: 4`（18 回合里 4 个是「只写了没申报」），覆盖率 **50% → 约 72%**（4 present + 4 write-only + 4 两者都有 / 8 with_doc）。

**代价**：约 80 行产品代码 + 断言；`state` 需要区分 `delivered` 与 `produced` 两种来源（**不能混进同一个数组** —— 上一轮 `source` 字段的教训就是「一个字段名装了两个断言」）。

### 5.2 必须补：P2 —— 订阅 `workspace/changes`，但只用作「有没有东西可看」的信号

> **2026-11-21 判定：不做。** 用户 m35456 原文「P2，P3直接判定飞起」——P2 与 P3 一并放弃，本节保留作为「想过、评估过、决定不做」的记录，不再是待办。
>
> 放弃的不是「这一项做不到」，而是「它不值得」。下面那句「收益是诚实的：它不提升命中率，只是把『没有』和『不知道』分开」正好也是放弃的理由：卡片答的是「这一轮交付了什么」，而一句「改了但没声明」回答的是另一个问题。轻量化项目只留回答主问题的东西。

**做法**：在 `record()` 里认 `workspace/changes`，记下 `{ turn, seq }`。**不解析它、不渲染它的内容**。

**理由**：真实会话里这个事件确实存在（4 条/1 条），它是宿主对「这一轮改了什么」的权威回答。但我们上一轮刚删掉 git 差分，**再把它请回来等于打自己脸**。

所以只做一件窄事：**当 `delivered` 与 `produced` 都为空、但 `workspace/changes` 存在时，卡片画一句「这一轮改动了文件，但没有交付声明」** —— 让空卡本身成为信息，而不是看起来像坏了。

**代价**：约 20 行 + 一条文案。**收益是诚实的**：它不提升命中率，只是把「没有」和「不知道」分开。

### 5.3 可选：P3 —— shell 里的写入（Qoder `I_0` 那一层）

> **2026-11-21 判定：不做。** 与 P2 同一条指令（用户 m35456）。本节末尾「如果做，先做这三件事」因此永远不会被执行，保留只为说明这条路当初被拒绝到什么程度。
>
> 顺带记下当初的三条反对意见，它们没有因为这次判定而失效，只是不再需要有结论：正则抽代码里的写入必然有假阳性；Qoder 自己在 `reportlab` 上也是硬编码特例；回来一半会让人以为整条 shell 解析器都回来了。

**做法**：只做 Qoder `I_0` 里**最窄的一条**：`python`/`node` 的 heredoc 或 `-c` 正文里，正则抽 `open(...,"w")` / `Path(...).write_text` / `writeFileSync`。**不碰重定向、不碰 `cp`/`mv`、不碰 `tee`、不碰 `curl -o`**。

**理由**：`session-151cb1ab` 正是这一种（bash 里跑 python 写报告）。不补它，那个会话永远是空卡。

**为什么不建议现在做**：
- 这是**我们刚删掉的 431 行 shell 解析器里最深的一层**，回来一半会让人以为整条都回来了；
- 正则抽代码里的写入**必然有假阳性**（读文件的正则、注释里的字符串、测试 fixture 里的写入示例）；
- Qoder 自己也只做到「正则」这一层，且 `reportlab` 那段是硬编码的特例 —— 说明这条路的通用性很差。

**如果做，先做这三件事**：① 只在零声明且零 `produced` 时启用；② 只认白名单后缀；③ 卡片上给这类行一个可区分的标记（比如 tooltip 写「由脚本写入」），**让读者知道这一行比 `present` 弱**。

### 5.4 明确不补（附理由）

| 不补 | 理由 |
| --- | --- |
| **通道 1（正文 markdown 链接）** | 宿主注释原文 `never from presentation data or the closing prose`。而且实测：正文任意绝对路径 357 个只有 7 个（2%）是真正的 artifact，噪声率 98% |

| **`apply_patch` 的 `*** Add File:`** | DSH 没有 `apply_patch` 工具 |

### 5.5 一条不该照抄的：`rewindState` 守卫
