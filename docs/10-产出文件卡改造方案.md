# 10 · 产出文件卡的改造方案（对齐 Qoder，但只抄能抄的）

本文是 [`09-Qoder产出文件机制逆向.md`](./09-Qoder产出文件机制逆向.md) 的后续：09 说 Qoder 怎么做的，本文说**我们改什么、不改什么、为什么**。

**本文不含代码改动。** 三个阶段都要你点头后才动工程。

## 一句话结论

Qoder 那套东西里，**只有一半能抄**：数据模型和生命周期（文件还在不在、哪个轮次改的）属于我们自己的代码，随时能加；六种打开方式和预览栈属于**宿主能力**，DSH 没有对应 API，硬抄就是造假动作。

所以方案的核心是：**把「路径清单」升级成「带状态和归属的产出记录」，其余一律不碰。**

## 先说不能抄的三件事

这三条不是"以后再说"，是**现在做不了**，写在这里是为了避免方案里埋下做不到的承诺。

### 1. 六种打开方式 —— 宿主只有一种

Qoder 的六个去向里，只有「在右侧栏查看」有对应物：

| Qoder | 我们这边 | 结论 |
| --- | --- | --- |
| 在右侧栏查看 | `sidebarRight.openResource(address)`（`client.js:2796`） | **已有** |
| 新窗口查看 | 无 | 做不到 |
| 内置浏览器 | 无 | 做不到 |
| 系统浏览器 | 无 | 做不到 |
| 默认应用 | 无（要 `shell.openPath`，客户端 bundle 里没有这个能力） | 做不到 |
| 计划文件 | 我们没有 spec 产物这个概念 | 不适用 |

`packages/ui-evolve/README.md:325-335` 已经把现状写清楚了：宿主暴露右栏，行在 `canPreview === true` 时是 `<button>`，否则是 `<div>`，点击包 `try/catch`。**这个设计本身是对的**——它诚实地表达了"这个宿主能预览"和"不能"的区别，比装作有六个入口要强。

按文件记忆打开方式（Qoder 的 `artifactFileOpenModes`）也因此无意义：只有一个选项的东西不需要记住偏好。

### 2. 预览栈 —— 已经外包给宿主了

Qoder 花了大力气做预览弹窗、四态渲染器、HTML 消毒、空图检测。我们一行都不用写，因为**右栏预览是宿主自己实现的**，`openResource` 把地址交过去就完事。

真要说借鉴，只借鉴一点：**Qoder 把"为什么没内容"拆成五个 reason**（空/坏/没了/太大/不支持）。右栏预览失败时我们看不到原因，但我们可以不去编造一个"预览失败"的提示——**不知道就别说话**，这比错误提示更准确。

### 3. 云端身份 —— 架构上没有这一层

Qoder 的产出有 `artifact_id`、能上传、能被远程任务消费。我们是纯本地插件，`$DSH_HOME/plugin-data/skill-evolve/sessions/<sessionId>.json` 是唯一存储。硬造一个 ID 只会增加一个要维护的不变式。

## 要改的三件事

以下三条按**价值 ÷ 成本**排序，可以只做第一条就停。

### P0：不存在的文件要留在卡上，而不是消失

**这是最值得抄的一条，也是最便宜的一条。**

现状：`packages/ui-evolve/lib/api.js:443-446` 对 `stat` 失败的文件**静默丢弃**，注释写的是：

> Not there, or not readable. The panel says "edited", not "exists", so a missing file is a legitimate answer and needs no warning.

这个理由在它自己的语境里成立，但它带来一个真实的信息损失：用户看到卡片里某个文件不见了，**无法区分「它不曾存在」「它被删了」「它被移动了」**。Qoder 明确选了另一条路——`missing` 是四态之一，行保留、标题加删除线、tooltip 说「文件已被删除或移动」。

改法：

| 文件 | 改动 |
| --- | --- |
| `api.js:423` `statTouchedFiles` | catch 分支不再 `continue`，产出一条 `{ path, missing: true, address, turn, noise }`；成功分支补 `missing: false` |
| `api.js:941` | 调用方无需改（返回值形状兼容） |
| `client.js:2468` | `openable` 追加 `&& file.missing !== true`，缺失行渲染成 `div` |
| `client.js:2472-2474` | 缺失行加 `data-missing="true"`、`className` 追加 `dsse-row-missing`、`title` 改为「文件已被删除或移动」、不加 `onClick` |
| `client.js` CSS | `.dsse-row-missing .dsse-name { text-decoration: line-through; }` + 降透明度 |

**必须同时加的守卫（否则会失控）**：`MAX_PATHS` 是 200（`session-state.js:69`），一个跑了很久的会话可能有大量历史文件被删。所以：

1. 缺失行只在**展开态**显示，折叠态不占四个宝贵位置 —— 折叠态是「这轮做了什么」，删除线文件不属于这个问题的答案
2. 缺失行按 `mtimeMs` 排到各分组末尾，而不是按原有顺序插在中间
3. 缺失行总数上限 20，超出后只显示「另有 N 个已删除文件」一行汇总

**不做**：不给缺失行提供"重新生成"按钮、不给它订阅文件系统变更（Qoder 的 `artifactFileStatusService` 那套合批 + 并发上限 + 80ms 调度器，是为「几百个文件同时查状态」设计的；我们每 8 秒轮询一次只为渲染一个卡片，直接 `stat` 就够，**不要提前引入状态服务**）。

验收标准：`test/api.test.mjs` 加一例「文件 stat 失败时仍返回带 missing 标记的条目」；`test/client.test.mjs` 加一例「missing 行不是 button、带 line-through、无 onClick」。两者都要跑 `node scripts/mutate-checklist-panel.mjs` 确认删掉实现后测试会红。

### P1：记录「哪个轮次改的」，让折叠有意义

现状：`session-state.js:120` 的 `paths` 是 `Map<path, sequence>`。`turn` 这个标记来自 `api.js:440`：

```js
turn: turnPaths === undefined ? false : turnPaths.has(absolute)
```

而 `turnPaths` 是从 `previous.paths`（**上一轮**的 transcript）算出来的（`api.js:936-940`）。所以「本轮」这个标记只在刚结束后一小段时间内准确，轮次一多就全靠 `sequence` 排序，**没有任何持久化的轮次归属**。

Qoder 每条 highlight 都带 `turnId`。改法：

1. `session-state.js` 的 `paths` 从 `Map<path, number>` 升级成 `Map<path, { at: number, turn: string }>`
2. 加载时兼容两种形状（旧文件是纯数字，`session-state.js:122-125` 已经在按 `typeof at !== 'number'` 过滤，改成两种都接收）
3. `rememberPaths(sessionId, paths)` 增加第二个参数 `turnId`；调用点 `index.js:371` 目前写的是 `rememberPaths(agentId, ended)`，需要把轮次 id 一并传下来
4. `pathsSeen()` 返回 `[{ path, turn }]` 而不是 `string[]`，`api.js:929` 与 `api.js:941` 相应调整

**收益**：折叠态不再靠统计推断「哪些是这轮改的」，而是读持久化的事实。会话重启后仍然正确（现在是重启即失忆）。

**代价**：状态文件格式变更。必须保证**旧文件可读**——这是硬约束，`session-state.js:117-119` 的注释已经把这条当作既有约定（"Absent in every file written before..., and that is a readable state, not a broken one"）。老会话升级后只是 `turn` 为空，从下一轮开始积累。

### P2：卡片头部说清「文件」与「生成文件」的关系

现状：`client.js:2105-2109`

```js
const fileMeta = filesOpen === true
  ? `全部 ${ordered.length} 个`
  : noisy.length === 0
    ? `${people.length} 个文件`
    : `${people.length} 个文件 · ${noisy.length} 个生成`
```

这套计数逻辑本身比 Qoder 的还细（Qoder 只有「显示其余 N 个」）。但它有个缺口：**折叠态下 `people.length` 可能远大于屏幕上那 4 行**，头部说「12 个文件」而只看到 4 行，读者得自己推「还有 8 个在展开里」。

Qoder 的做法是把差值直接说出来（`showMore(remaining)` = 「显示其余 8 个文件」）。建议：`badgeAction.label` 从 `展开全部 ${ordered.length} 个`（`client.js:2442`）改成 `展开其余 ${ordered.length - FOLDED_FILES} 个`，折叠态数字与头部数字就此对上。

这是一行的改动，但它是这套卡片里**唯一一处两个数字互相矛盾**的地方。

## 明确不做的

写下来是为了以后不被"Qoder 有啊"重新拉回讨论：

| 项目 | 不做的理由 |
| --- | --- |
| 任务监控面板（五分区分组） | 我们的面板只有一列，硬拆五个区会把「上一轮 / 技能与 MCP / 产出文件」三张卡变成九个格子。Qoder 有整块浮层，我们没有 |
| `origin: manual/automatic` | 没有「手动添加产出」这个交互，字段永远是 `automatic` |
| 文件存活状态服务（订阅 + 合批 + 并发上限） | 见 P0 的「不做」，过度设计 |
| 悬停预览 | 右栏预览已经够用，悬停预览要在卡片里内联渲染，等于把预览栈搬回来 |
| HTML 消毒 / CSP | 我们不渲染 HTML，宿主负责 |
| Figma embed 特例 | 为单个合作方硬编码的 hostname 白名单，不能称为机制 |
| 内容哈希（`artifactHash`） | 唯一有意义的用途是"判断文件是否被外部改动"，而我们每次轮询都 `stat`，`mtimeMs` 已经回答了同一问题 |

## 实施顺序与工作量

| 阶段 | 内容 | 涉及文件 | 预估 |
| --- | --- | --- | --- |
| P0 | 缺失态保留 + 渲染 + 三类上限守卫 | `api.js`、`client.js`、CSS、2 个测试 | 半天 |
| P1 | paths 结构升级 + turn 持久化 | `session-state.js`、`index.js`、`api.js`、`session-state.test.mjs`、`persistence.test.mjs` | 一天（格式兼容是主要风险） |
| P2 | 折叠文案对齐 | `client.js` 一行 | 十分钟 |

**P0 与 P1 可以独立做**，P1 不依赖 P0。P2 随手。

## 风险

| 风险 | 应对 |
| --- | --- |
| P1 破坏老会话状态文件 | 双形状加载 + `test/persistence.test.mjs` 加旧格式回归例；先写测试再改结构 |
| P0 让卡片变长、折叠态失去意义 | 缺失行不进折叠态 + 总数上限 20 + 汇总行 |
| `client.js` 是手写 bundle，改完忘了同步 | 已有规矩：`npm run sync` + 重启宿主。`docs/00-文档索引.md:62` 记着"历史上已因忘记同步出过两次错" |
| 改动被误认为"抄了 Qoder 代码" | 本文只借**行为规格**；实现全部按本项目既有风格重写，不复用 Qoder 的标识符、常量名或结构 |

## 需要你决定的三件事

1. **P0 的缺失行要不要进折叠态？** 我的建议是不进（折叠态回答"这轮做了什么"），但如果你希望"文件被删了要立刻看得见"，那就得进，代价是折叠态从"四个正常文件"变成"可能四个都是删除线"。
2. **P1 做不做？** 它是唯一需要动状态文件格式的改动，也是唯一能让折叠态在**会话重启后**依然准确的东西。如果产出卡不是高频使用场景，可以跳过。
3. **要不要只做 P0 + P2？** 这两条加起来半天，覆盖了用户能直接感知的全部差异（文件消失、数字对不上）。P1 是给重度用户的长线投入。

你定完这三条，我再动代码。
